# 持久化安全与失败语义

## 原子文件写入

`core/AtomicFileWriter` 只承担字节写入：检查目标类型，使用禁止直接写入降级的 `QSaveFile`，校验完整写入和 commit 的结果。偏好设置、报告内容写入等使用它；活动工程写入另由 `ProjectFileTransaction` 增加写锁、版本复核和上一版本保护。格式序列化仍由各自模块负责。

HTML 导出的最终目标提交目前由 `ProofreadChangesDialog` 中的 `commitTemporaryExportFile()` 使用 `QSaveFile` 完成，并非所有最终提交都经过同一个 helper。后续可将这段纯 IO 移入服务层，不能因此省略目标提交校验。

工程保存失败不能清除 dirty；偏好保存失败不能应用新配置或显示成功。报告临时文件生成成功也必须表示内容完整，不能仅表示文件打开成功。

原子替换解决的是单个文件的可见完整性，不等于对硬件损坏、所有文件系统或多个文件提供断电事务保证。

## 偏好设置保存

`services/preferences/PreferenceStore` 为每份设置草稿持有独立磁盘基线，复用 `FileRevision` 和
`AtomicFileWriter`，不使用工程备份事务。成功读取时，从实际解析的同一份 JSON 字节计算 SHA-256；
文件不存在也作为明确基线。`compareExternalChanges()` 只比较，不接受或推进外部版本。
读取、版本复核和写出共用 `BoundedJsonIo`：JSON 字节最多 4 MiB，值节点总数（含根与容器）最多 10000，
根按第 1 层计，最大深度 32。超限读取或保存不推进基线、不应用设置；输出预算在取得写锁前校验。
保存时通过目标路径旁的 `.lock` 文件取得非阻塞 `QLockFile`，持锁复核存在状态和内容摘要，再原子提交。
只有成功读取或提交才更新基线；锁竞争、外部修改、读取或写入失败均保留草稿，不应用新设置。

`PreferenceDialog` 从磁盘建立草稿和对应基线，仅在保存成功后发出 `preferencesApplied`。
外部冲突不提供强制覆盖或自动合并，重新载入前需确认丢弃尚未保存的本地修改。
该锁只协调遵守同一锁协议的写入者；摘要复核与原子提交之间仍有竞态窗口，不能阻止不使用锁的外部编辑器同时写入。
`PreferenceStoreTests` 覆盖旧草稿与同时保存竞争、文件创建/删除、锁占用、失败重试及失败时不应用或关闭窗口。

## 并发保存与上一版本

应用层工程写入使用 `ProjectFileTransaction`，通过规范化目标路径对应的 `.labelqt-write.lock`
协调 LabelQt 实例。普通保存、另存、合并输出、新建、图片改名和恢复共用此边界。
锁竞争或目录权限错误直接失败，不阻塞 GUI 等待；dirty 和撤销状态不因此清除。
“另存为”若通过符号链接或路径别名指向当前工程，按写锁使用的规范化目标判断为普通保存，
仍检查原加载/保存版本，不能借别名跳过冲突检查。
图片改名/恢复的锁覆盖全部文件动作及失败回滚，而不只是最后的 TXT 写入。
`RenameDirectoryLocks` 另对恢复日志目录和所有涉及图片目录取得规范化的 `.labelqt-rename.lock`，
用于协调不同 TXT 共用图片的事务。统一顺序为 TXT 写锁、排序去重后的目录锁；全部非阻塞获取，
任一失败释放本轮已取得的目录锁。恢复持锁后重新核对日志，防止使用加锁前读到的旧材料。
该协议防止协作事务交错，不会自动改写其他引用这些图片的工程，也不能阻止外部图片工具修改文件。

先完成序列化和临时输出写入，复制并校验上一磁盘版本，再紧邻原子提交复核目标摘要。
新文件通过 `writeNew` 拒绝并发出现的同名文件。已有工程覆盖前保留同目录
`<工程文件名>.labelqt-previous`，不受自动备份开关影响，在恢复列表中作为普通备份展示。
它保存上一次磁盘内容，不是无限历史，也不能替代独立备份。

锁是协作式的：外部编辑器、旧版 LabelQt 和某些网络文件系统不会遵守它。
最终摘要检查与原子替换之间仍有系统调用级窗口，不承诺对这些外部写入提供跨程序 compare-and-swap。
不要让多个不同工具同时写同一工程；上一版本副本也不能保证捕获恰好落在最终窗口内的外部修改。

## 外部修改检测与重载

`ProjectController::storageChanged` 在成功加载、保存、另存或文件事务更新后发布持久化基线变化。
`ProjectFileMonitor` 仅消费工程路径和 `FileRevision`，不持有活动工程引用、不推进保存基线。
它监听文件及父目录，文件被原子替换或重建后重新挂接；事件防抖 400 ms，另有 5 秒轮询和应用激活补查。
轮询会校验内容摘要，而不只依赖修改时间；大文件或慢速存储会增加读取成本。
后台只处理值，单个 monitor 同时最多一个读取任务；前后摘要不一致则重试。
内容变化时校验工程可解析性，同一已验证有效内容不重复解析，失败结果在后续检查中重试。
会话/基线代数不符的旧结果不能更新状态。
销毁 monitor 不要求等待读取结束，GUI 侧 watcher 断开后，后台没有可访问的工程或控件指针。

`ProjectExternalChangeController` 负责状态栏入口、同一观察版本的提示去重和安全时机调度。
主窗口未激活、模态窗口/菜单打开、自动化准备或执行期间不主动弹窗；恢复可操作后再询问。
因此页面管理草稿、校对窗口、重命名确认和导出流程不会被外部重载打断。
观察到变化不代表接受变化：“保留当前版本”不修改 `savedRevision`，普通保存仍经过原有冲突保护。
自身写入通过成功提交的内容摘要识别，不设置会吞掉外部事件的保存期忽略窗口。

提示复用 `ProjectRecoveryController` 的比较、另存、重载和明确覆盖入口。
先由 `EditorStateController` 提交文本框内容到内存，不能用普通保存来准备外部重载。
有本地修改时，重载前通过 `ProjectRecoveryService::preserveLocalEdits` 在备份目录生成唯一的
`before-reload-<UUID>.txt` 和恢复索引，作为非自动备份保留。备份失败则不调用加载入口。
用户确认针对已观察到的磁盘摘要；确认期间再次变化、读取失败或解析失败，保留内存工程、dirty 和撤销历史。
成功重载才重置任务会话并清空撤销历史；旧任务即使迟到也不能提交到新会话。
页面与标签按本机 `ProjectSessionState` 中的稳定 ID 恢复，找不到页面时退回同名页或邻近页；
旧 ID 无法匹配时不猜测标签对应关系。缩放与视图中心复用现有延迟恢复入口。

文件消失或损坏时保留内存工程，禁用无效的比较/重载操作，允许另存副本或明确确认覆盖。
目录/文件监听失败时继续轮询，不保证捕获两次检查之间出现后又消失的内容，也不替代最终保存校验。
不会自动合并外部内容，不提供任意外部编辑器参与的强一致写锁。

`LabelPlusDocument::readFromFile` 从同一份原始字节返回解析结果和 SHA-256，保留 BOM 自动识别能力。
文件读取、备份预览、改名日志快照和移动导入共用 `readFromBytes` 的严格解码；无 BOM 默认 UTF-8。
拒绝非法/截断编码、无效 Unicode 和 NUL，不把替换字符静默写回。UTF-32 额外检查字节对齐和无损往返，
兼容 Qt 解码器未报告部分无效输入的情况。解析时校验分组名；恢复提示逐项隔离重定位/序列化异常，
保留损坏材料供人工处理，不因此中断正常工程打开。
工程加载、备份预览与监听校验不仅比较前后磁盘摘要，也校验实际解析字节的摘要，避免文件在多次读取间
变化又恢复时接受中间版本。摘要包含原始 BOM/换行字节，不是规范化或重新序列化后的正文摘要。
目录、管道等非普通文件和悬空符号链接在打开读取前拒绝，避免常见误选或外部替换导致的阻塞。
路径检查仍不能消除外部程序在检查与系统调用之间替换路径的所有竞态。

备份快照与索引均只创建新文件，不覆盖同名内容。多个实例同时选中同一备份名时，后写入者失败并保留
dirty/待备份状态；如果快照已写入而索引失败，保留无索引快照供人工恢复，不报告成功、不覆盖旧索引。
提示窗口与监听器允许先于后台结果销毁；发出观察信号或进入嵌套提示回调后，不再假设原对象仍然存在。

## 图片改名与工程提交

`ProjectController::renameImages()` 先保存旧工程，再调用 `ProjectImageRenameService`。服务从原工程生成独立候选状态，在文件改名完成后调用工程持久化回调；只有回调成功，才发布候选状态。

文件操作由 `services/io/FileRenameTransaction` 负责：

1. 记录 source / temporary / target 映射。
2. 全部来源先转为同目录的唯一临时文件。
3. 全部临时文件转为目标名。
4. 提交新工程，成功后清理恢复映射。

失败回滚也分两阶段：先把所有已落地目标回收到自己的临时路径，再恢复原始路径。不能直接逐项 target → source，因为来源和目标可能构成链或循环。

如果外部文件占用、权限变化或介质错误阻止回滚，不覆盖外部文件，也不删除尚未恢复的图片；错误列出失败路径，并保留 `.labelqt-rename-*.json` 和临时图片。v2 记录包含文件 SHA-256 和前后工程快照，由 `ProjectRecoveryService` 验证并恢复。旧记录只供人工核查。工程控制器检测到同目录未解决记录时阻止打开和保存；新改名事务也拒绝执行。不能直接删除记录绕过保护。
合并输出也在工程写锁范围内通过同一恢复门禁，不能用覆盖合并结果绕过未完成事务保护。

普通失败且回滚成功时，磁盘工程仍是已保存的原状态，内存工程和页面管理草稿不发布新文件名。`ProjectWorkflowController` 只在整个提交成功后清空普通撤销历史。UI 在可能替换项目容器前解除表格等视图的引用，并在成功和失败两条路径都重新绑定和恢复视图。

有待处理文件操作时，页面管理将完整最终页序一并交给提交服务，成功后不再重复应用旧索引。纯页序调整仍是普通可撤销工程编辑。移除页的文件指令在草稿中同步剪裁，服务边界也拒绝对已移除页执行隐藏文件操作。

## 本地记录预算

恢复索引、重命名日志和审阅会话通过 `BoundedJsonIo` 限制读取字节、嵌套深度与结构节点；
拒绝符号链接和非普通文件。写出端使用相同限制，避免产生下次无法恢复的记录。

| 记录 | 限制 |
| --- | --- |
| 备份索引 | JSON 64 KiB；备份快照 16 MiB |
| 重命名恢复日志 | JSON 64 MiB；最多 10,000 次移动；前后工程快照各 16 MiB |
| 审阅会话 | JSON 16 MiB；状态记录与人工配对合计 10,000 项；解码文本合计 16 MiB |

JSON 最大深度为 32，并有按记录类型设置的结构节点预算。超限备份 / 改名在修改目标文件前失败；
无效恢复材料保留供人工核查，不自动删除。`ProjectRecoveryDialog` 使用服务返回的结构化详情，不能自行重读 JSON。
`ReviewSessionService::validate` 同时用于面板修改前和本地写出，工程内记录与本地记录遵守同样约束。
已有批注兼容读取与保存，但不再提供新增 / 编辑入口。`RecordStorageTests` 覆盖边界、拒绝非法输入及失败后保留原材料。

## 正文与格式兼容

LabelPlus 结构行只按整行识别。正文中的独立 `-`、`关联文件:`、普通行首尾空白和内部空行不再当作头部信息处理。

经典格式在标签末尾使用空行分隔，无法无歧义地表达正文末尾空行；不同工具还可能规范化 CR/LF。因此 `LabelPlusDocument` 在统一 `LabelQtMetadata` 中维护可选的 `labelText` section，仅为需要保真的标签保存原文与正文 SHA-256。重新打开时，页名、可见标签索引和正文校验都匹配才恢复原文，避免覆盖外部工具修改后的文字。

`labelText` 由当前标签重新生成，不作为 UI 状态；软删除标签不计入可见索引。其他工具移除该私有 metadata 后，仍可读取经典正文，但无法恢复这些原本有歧义的结尾空行/换行编码。

正文若包含独占一行的完整页面或标签结构头，则保存前明确报错，保留旧文件。不要用不透明的文本替换掩盖格式歧义。损坏或不支持的统一 metadata 在工程读写入口明确报错；展示服务仍可通过宽容读取接口得到空结果，避免在 UI 回调中新增未捕获异常。

持久化页名必须非空且唯一，读取旧工程也不例外。身份、来源和正文保真元数据均以页名关联，不能容忍静默覆盖。
统一元数据限制压缩输入为 16 MiB、解压 JSON 为 32 MiB，Base64 拼接也有上限。
zlib 流式解压同时验证声明长度和实际产出，拒绝伪造长度、截断和尾随数据；写入端遵守同一限制。

## 自动化窗口生命周期

异步结束回调建立时就捕获 `QPointer<AutomationRunDialog>`，不能等回调运行后再从原始地址创建 QPointer。运行中的 Esc 和关闭动作只隐藏日志窗口；任务结果应用到工程后才解除编辑锁。窗口隐藏不代表取消脚本，取消仍由明确的取消动作发出。

准备参数和读取钥匙串同样属于运行期。控制器为每次运行持有独立状态，避免嵌套事件循环重入后串用任务和窗口。

## 可取消后台任务

对比与 HTML 导出共用 `ui/widgets/BackgroundTask.h` 的等待逻辑。对话框拒绝始终表示取消，
即使 worker 已完成但 finished 通知尚未送达也不能提交 HTML。取消未结束的导出仅等待后台清理临时文件，
不再修改用户选定的目标文件。工作线程抛出的导出异常转换为错误结果，不越过 GUI 回调边界。

## 验证

`PersistenceSafetyTests` 独立覆盖原子写入失败、正文往返、元数据保护、链式/循环改名各阶段故障、保存提交失败与异常、回滚受阻时保留证据、dirty/undo 状态和运行中日志窗口 Esc。
`PersistenceReviewTests` 覆盖跨进程共用图片锁、回滚/恢复锁、目录别名、合并恢复门禁、严格编码及坏恢复副本。

测试的重命名函数注入仅位于文件事务边界，不在 UI 中增加测试专用状态。`LabelQtTestSupport` 供现有测试与安全测试复用编译出的核心和服务实现。

`ProductWorkflowTests` 补充恢复协议、跨目录引用、保存冲突、草稿和审阅工作流回归。
`ExternalProjectChangeTests` 覆盖替换、原地编辑、删除重建、无效内容、自身保存、旧检测结果隔离、
忙碌/模态延迟、提示去重、版本限定重载、备份失败与实际重载确认流程，以及稳定 ID 选区恢复。
`AutomationTaskTests` 同时验证重载使旧任务结果失效。
外部变化回归还覆盖路径别名保存冲突、备份同名竞争、非普通文件拒绝、观察/提示回调中销毁对象，
以及 UTF-8、BOM/CRLF、UTF-16 输入的实际解析摘要。
`RiskRegressionTests` 覆盖表格快照生命周期、旧工程重名保护、有界解压、工程写锁和上一版本恢复、
图片加载销毁/失效、取消完成竞态及自动化准备重入。`AtomicFileWriter::writeNew` 用于恢复副本和新工程，拒绝已有目标。
操作说明和限制见 [产品工作流](product-workflows.md)。
