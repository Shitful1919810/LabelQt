# Android 移植实施方案

状态：设计基线及实施中技术预览。更新日期：2026-11-11。工作分支：`port-android`。

本文规定完整首版的产品范围、交互、存储边界和验收条件。仓库现有 ARM64 APK 构建目标和技术预览，
构建与当前限制见 [Android 构建](android-build.md)，不可把后文尚未完成的设计当作已实现功能。
当前成品的操作以 [使用说明](android-user-guide.md) 为准；实施时遵循
[Android 工程约定](android-development.md)，不要在 QML 或平台桥中复制共享业务规则。
实施进度在根目录 [TODO](../TODO.md) 维护；当前桌面行为仍以
[架构](architecture.md)、[持久化安全](persistence-safety.md)、[产品工作流](product-workflows.md)
和 [校对轮次](proofreading-rounds.md) 为准。修改本方案的安全边界必须显式说明，不得以适配为由静默降级。

## 1. 产品定位与决策

目标是让漫画翻译者和校对者在 Android 手机、平板上完成绝大多数现有工作，保持与桌面 LabelQt
及经典 LabelPlus TXT 的互通。优先保证平板高效，同时使手机可以独立完成编辑、校对和交接。

确定以下方向：

1. 同一仓库、共用 C++23 数据与业务内核。桌面继续 Qt Widgets，移动端采用 Qt Quick/QML。
2. 首版采用“导入副本 → 应用内工作区 → 保存/恢复 → 导出/分享”，不直接修改 QQ 文件或任意外部目录。
3. 普通标签、分组、页面与校对操作继续复用既有编辑、撤销、身份、版本和提交服务。
4. Android 不带 Python、脚本安装、pip、自动化菜单或脚本密钥设置；桌面功能不因此删除。
5. QQ 收发工程 ZIP 是首版必要场景，不是平台专属的一套工程格式。
6. 首版正式发布必须完成高级工作流和安全验收；中途仅能称为技术预览/编辑测试版。

不采用“把 MainWindow 缩小后放进 APK”，也不重写另一套 Kotlin 工程模型。
Qt 支持 Android，Qt Quick/Controls 更适合触控；Java/Kotlin 仅用于必要的平台桥接。
依据：[Qt for Android](https://doc.qt.io/qt-6/android.html)、
[Qt 界面技术](https://doc.qt.io/qt-6/topics-ui.html)。

## 2. 功能范围

“首版”指完整移动版，不等于最早可运行的 APK。下列保留项不得因开发后期时间不足被静默移除。

| 功能 | 首版安排 | 与桌面差别 |
| --- | --- | --- |
| TXT 打开、新建、保存、另存 | 保留 | 打开变为导入；另存分为工作区副本与导出 |
| 从图片创建工程 | 保留 | 系统选择目录或多张图片，导入后确认页序 |
| 标签增删、文本、分组、移动、排序、多选 | 保留 | 显式工具和触控选择，不要求修饰键 |
| 撤销/重做、复制粘贴、分组筛选 | 保留 | 按钮始终可达，文本剪贴板与标签剪贴板区分 |
| 图像缩放、定位、区域截图 | 保留 | 双指操作，选区截图可保存/分享，不依赖 Ctrl+C |
| 全文查找、范围筛选、替换预览 | 保留 | 独立页面；批量替换仍一次提交、一次撤销 |
| 校对轮次、批注、审阅状态、工程对比 | 保留 | 手机列表与详情切换，平板双栏 |
| diff 筛选、人工配对、HTML 报告 | 保留 | 沿用业务规则，人工配对仍只适用于外部比较 |
| 页面排序、移除、pending 改名、缺图修复 | 保留 | 只改工作区内文件；修复图片先复制进工作区 |
| 工程合并 | 保留 | 输入先导入/暂存，输出独立工作区，不覆盖输入 |
| 备份、异常恢复、最近工程、偏好、多语言 | 保留 | 恢复优先，布局与输入设置按平台展示 |
| ZIP 导入、ZIP/TXT/HTML 导出、QQ 分享 | 新增且首版必要 | 标准 ZIP、系统选择器与分享面板 |
| 外部工程变化检测 | 调整 | 本地工作区仍保护；外部来源只显式重导入/比较，不后台同步 |
| 鼠标、键盘、触控笔 | 基础支持 | 不依赖 hover；不做手写识别，笔尖按指针处理 |
| Python/OCR/AI 自动化 | 不纳入 | 不内嵌解释器，不引入替代云服务 |
| 外部目录原地写入、双向同步、多人实时协作 | 延后 | 另行设计授权、能力检查与冲突协议 |
| RAR/7z、加密 ZIP、分卷包、嵌套压缩包自动展开 | 不纳入 | 明确报错，要求用户转换为普通 ZIP |
| 跨进程恢复整个撤销栈、多轮校对历史 | 不纳入 | 恢复已落盘内容；校对沿用当前单轮模型 |

桌面专属设置如 QWidget 风格、hover 参数、Python 参数在移动端隐藏，不显示无效开关。
既有校对兼容限制不变：原版 LabelPlus 能读正文，但不展示私有批注/轮次；第三方改写可能使身份失效。

## 3. 工程与存储语义

### 3.1 四类对象不能混用

| 对象 | 身份/内容 | 寿命及写入规则 |
| --- | --- | --- |
| 外部来源 | URI、显示名、可选授权、导入内容摘要 | 只用于导入/再次选择；不当普通路径、不写回 |
| 本地工作区 | 独立 workspace UUID、TXT、已复制图片 | 可持续编辑，位于应用持久数据目录，不放 cache |
| 编辑/页面草稿 | 文档会话、目标 UUID、基准版本、未应用输入 | 与已提交 TXT 分开；恢复必须校验目标及版本 |
| 导出产物 | 某次固定快照、生成时间、摘要、目标 URI | 不可变，可重试分享；不能被后续编辑原位改写 |

建议工作区包含 `project/`（有效 TXT 与图源）、`recovery/`（恢复材料）、本机清单与草稿记录。
工作区 ID 与工程 ID 不同：再次导入同一 TXT 可以保留工程身份谱系，但必须获得新工作区 ID。
“复制工程为独立工程”则通过现有身份复制策略产生新身份。不能用文件名或工程 UUID 唯一定位本机工作区。

一个工作区只允许一个活动写会话；第二个系统打开请求激活现有会话或导入副本，不另开写入者。
不同工作区首版不通过硬链接共享可改名图片，避免一处改名影响另一工程。
本机清单/草稿采用版本化、有界记录；升级先验证并保留可恢复的旧版，迁移失败不以默认内容覆盖。
未解决事务材料不可被普通缓存清理删除。清单写入与工程发布中断时，可以从已验证的工作区记录重新收录，
不依赖单个列表索引成为唯一恢复入口。

### 3.2 用户可见状态

编辑区顶部用一个可展开的状态入口显示，不堆三排常驻提示：

- “有未保存修改 / 正在保存 / 已保存到本机 / 保存失败”：表示活动工程提交到工作区的状态。
- 状态详情显示“恢复草稿已保护至…”；草稿成功不能冒充工程已保存。
- “尚未导出 / 导出后有修改 / 已生成分享包”：单独表示交接状态，不与 dirty 或 UndoStack clean 混用。
- QQ 分享只能报告“已打开分享面板/已交给目标应用”，不能报告对方已收到。

“保存”处理当前编辑器后保存 TXT 到工作区；“导出/分享”先保存所选快照，再生成外部产物。
导出失败不能撤销已成功的本机保存，也不能清掉待导出标记。导出摘要需覆盖 TXT 与打包图源清单，
不能仅比较一个内存版本计数；导出期间允许的后续正文编辑仍显示“导出后有修改”。

默认提供“自动保存到本机”，经 AppPreferences 配置。关闭它仍保留恢复草稿保护；该保护与历史备份保留策略不同。
自动保存失败常驻提示并保留内容，不反复弹框。所有写完成通知只确认它实际保存的版本，不把旧结果当新版本。

### 3.3 导入流程

1. 入口是工程列表的“导入”、系统文件打开/分享意图、或“从图片新建”。
2. 将授权输入流复制到独立暂存区，限制实际读取量；不可 seek 的 URI 也通过同一复制入口处理。
3. 验证 ZIP/工程，列出工程候选、图片数量、缺图与空间估算。多个 TXT 必须由用户选择，不能取第一个。
4. TXT 没有图片时允许作为缺图工程导入；可补选图片目录。选择 TXT 不等于获得其兄弟文件权限。
5. 只复制选定工程的必要文件及明确选择的图源；验证后发布完整工作区。取消/失败不出现半份可编辑工程。

目录导入不承诺跨外部修改者的原子快照：复制时检测可观察到的变化，变化时重试或让用户重新选择。
ZIP 先完整接收并验证再扫描；URI 已失效时提示重新选择，不循环读取。
遇到重复导入，以内容摘要提示“打开已有副本 / 导入新副本”；同名不同内容不能自动覆盖。

经典 TXT 的相对路径和私有 `imagePaths` 都要经过导入路径解析边界：不能自动读取包外、设备绝对路径、
`content://`、网络 URL 或父目录逃逸引用；只允许在已授权且已暂存的根内解析，其他作为缺图待修复。
不为“修复缺图”静默申请访问整个设备。历史校对图源同样遵守边界，缺图不应阻止正文查看。

### 3.4 导出与原版兼容

- “完整工程 ZIP”：默认交接方式，包含标准 TXT 和其当前页面图片；解压后可直接用桌面版打开。
- “仅译稿 TXT”：适合对方已有同名图源；改过图片名时提示需同步图源，不能声称是完整工程。
- “校对 HTML”：使用当前筛选，包含批注和状态；沿用报告服务，不在移动 UI 重新实现 diff。

默认 ZIP 中一个工程目录，TXT 与当前页面图源按经典读取规则安排；不要求收件方安装专有解包工具，
不以自定义扩展名替代 ZIP。默认保留统一校对元数据，但不包含本机 URI、工作区绝对路径、草稿、备份、
恢复日志、偏好、密钥、脚本和其他工程。分享预览说明会包含图源、译文及校对记录。
这里的路径清理针对应用管理的路径字段，不任意改写用户正文、批注和普通注释；用户自己写入的隐私内容
仍可能被分享。未知元数据不能为脱敏直接丢弃，无法确定安全导出方式时应提示并阻止有损转换。

导出使用独立候选工程，通过 ProjectLocationService 等共用路径规则重定位；不得为打包改写活动工程。
同名图源、大小写冲突或 Windows 不合法名称先给出可审阅的包内改名计划；统一迁移候选引用及 metadata，
保留身份和历史页名语义。无法安全映射则阻止完整导出，不能扁平覆盖或丢页。
历史快照引用无法获得原像素时继续标示不可用，不冒充保存了历史图片。
缺图时默认阻止“完整”包，可明确选择“导出不完整工程”，并列出缺失页；正文不能因此丢失。

先在应用私有导出目录完成并验证产物，再输出到用户新建的目标文档。首版不提供覆盖原外部文档。
外部提供者写入不保证原子性；中断时尽力删除本次新建的不完整文档，失败则保留目标位置和说明。
无法读回校验时明确区分“写出完成但未读回验证”，保留本地完整产物供重试。

## 4. QQ 与标准文件交接

### 4.1 发给 QQ

工程内“导出/分享”选择完整 ZIP 或仅 TXT，预览名称、范围、估算大小、缺图和校对记录，再生成文件。
生成成功后调用 Android Sharesheet，用户选择 QQ 和联系人/群。首版不绑定 QQ 包名、登录 SDK、
聊天记录或自动发消息；QQ 只是一个接收应用，其他支持文件的应用也可以接收。
标准二进制分享使用 `ACTION_SEND`、`EXTRA_STREAM`/`ClipData`、正确 MIME 和临时只读 URI 授权。
依据：[Android 分享文件](https://developer.android.com/training/sharing/send)。

分享产物放在应用持久私有的 `outgoing` 目录，而不是易被清理的临时 cache。通过受限 FileProvider
只暴露这一目录中已完成、不可变的单个文件，不能暴露整个工作区或根目录；不发送 `file://`。
依据：[安全文件分享](https://developer.android.com/training/secure-file-sharing/share-file)。

返回 LabelQt、选择了 QQ、或分享 Activity 返回，都不能证明上传完成。保留产物至少 7 天作为首版默认
清理策略，超时只表示可清理，不表示 QQ 已读取；不在分享回调内立即删除。空间不足时展示旧产物列表，
用户确认后清理，提醒正在发送的文件可能受影响。系统/用户强行清数据仍可能打断传输。

当前技术预览已实现七天过期清理与 2 GiB 分享缓存上限，启动/每小时/导出前串行维护；
超限时拒绝新导出，尚未提供逐包手动清理界面。分享默认原 ZIP 名且允许本次修改；
每次发布独立 UUID 目录，保持文件名可读且不覆盖旧分享。

QQ 未安装、未出现在分享面板、拒绝类型或文件过大时，提供“保存 ZIP 到系统文件位置”，用户再从 QQ
发送文件。不承诺固定 QQ 大小上限，也不通过重新压缩图片降低画质；不做自动分卷。

### 4.2 从 QQ 打开

支持两个互补流程：

1. QQ 下载完成后选择“其他应用打开/分享”，若该 QQ 版本提供此入口，选择 LabelQt。
2. 在 LabelQt 中“导入 ZIP”，通过系统文件选择器选取 QQ 已保存到可访问位置的文件；必要时先在 QQ
   另存到系统可访问目录。不得硬编码 QQ 下载路径，不申请所有文件访问权限来扫描 QQ 私有目录。

平台入口接收 `ACTION_VIEW` 和 `ACTION_SEND` 的受支持 URI；处理首次启动及已有 Activity 的新 Intent。
以 `data`、`EXTRA_STREAM`、`ClipData` 规范化为一份导入请求并去重，拒绝混淆/互相矛盾的输入。
首版每次只导入一个包，多文件请求给出选择，不自动合并或静默忽略其余文件。
Android 接收其他应用数据的基础机制见 [官方说明](https://developer.android.com/training/sharing/receive)。

Intent filter 优先 ZIP 的标准及常见 MIME 和 TXT；`application/octet-stream` 若经真机确认为必要，
才以窄范围补充并测试错误接管其他文件的行为，不注册全类型 `*/*` 来抢占打开入口。
MIME、后缀、显示名均不可信，最终由实际字节和解析器验证；缺扩展名可提示识别结果后导入。
QQ 传递的临时读授权可能不能持久化：授权有效期间尽快有界复制，不能只保存 URI 等下次再读。

收到包时若正在编辑：先接收文件到暂存队列，不强行切换工程；显示导入入口。当前工程保存或草稿保护失败
则保留当前会话；用户可以延后处理新文件。页面管理/文件事务期间不插入新的确认窗口。
重发 Intent 不自动复制多份工作区；队列有数量/字节上限，不允许外部应用用连续请求耗尽空间。

**QQ 兼容性验收必须用真实 QQ。** 本方案基于 Android 标准接口，并未验证某个 QQ 版本是否暴露打开入口、
传递何种 MIME、何时读取文件。记录 QQ 版本、Android/OEM、冷/热启动和收发步骤；失败时保留手动选择兜底。

### 4.3 ZIP 安全与编码

复用一个跨平台归档服务，不让 Java 和 C++ 各写一套解压规则。优先验证裁剪后的 libarchive ZIP 读写，
只开放 ZIP 与需要的压缩方法，不因库能处理多种格式就全部开放。当前仓库未链接 libarchive。
上游支持 ZIP 读写且提供 BSD 许可；实施时锁定版本、审计可选依赖并记录许可，而非追踪 master。
依据：[libarchive](https://www.libarchive.org/)、[上游许可证](https://github.com/libarchive/libarchive/blob/master/COPYING)。

- 只接收普通文件/目录；拒绝符号链接、硬链接、设备、绝对路径、盘符/UNC、NUL、父目录逃逸及混合分隔符绕过。
- 提取到全新私有目录；每个目标都验证位于暂存根内，拒绝重复项、文件/目录冲突和规范化后重名。
- 对大小写及 Unicode 规范化碰撞作显式诊断；不静默改名使 TXT 引用失配。异常路径不靠字符串前缀判断安全。
- 按实际流量限制包、单项、总解压大小和条目数，验证 CRC/截断；不信任中央目录宣称的长度。
- 检测到加密、分卷、不支持压缩方法或嵌套包时明确提示，不执行内含脚本或嵌入 HTML。
- UTF-8/有效 Unicode 名称优先；旧 ZIP 编码不确定时提供受限编码预览及重新扫描，不凭猜测发布乱码工作区。
- 不接受 QQ 发送的路径作为应用内部目的地；导入 TXT 的引用也必须走第 3 节边界。

初始工程预算建议：输入 ZIP 2 GiB、实际解压总量 8 GiB、单个图源文件 512 MiB、条目 10000、
目录深度 32、排队待接收包 3 个且总输入不超过 2 GiB。它们是待真机调优的产品限制，不是设备承载保证；
仍受实时可用空间约束，TXT/metadata 使用既有更严格预算。实现应集中定义并测试边界，不散落 magic number。
空间估算覆盖输入暂存、解压、候选图源、恢复副本和最终 ZIP 同时存在的峰值，不能只看 ZIP 大小；
流式复制逐段检查配额。低空间时只能清理本应用可确认归属的暂存文件，不自动删除用户工程或未解决事务。
解压膨胀、磁盘写满、取消、进程被杀只能遗留可识别暂存材料，不得改到已有工作区。
安全依据：[Android ZIP 路径穿越](https://developer.android.com/privacy-and-security/risks/zip-path-traversal)。

## 5. 页面布局与视觉

### 5.1 导航结构

启动进入最近工程列表，可继续上次工作；有恢复事务时先展示恢复入口，不直接进入可写状态。
列表显示名称、缩略图、页数、最后编辑时间、本机保存/交接状态，不以绝对路径充当名称。
主操作为“导入”和“从图片新建”；工作区删除独立确认，提示只删应用内副本，且未导出修改会丢失。

工程内固定三大工作区：“编辑 / 校对 / 页面”。搜索、分组、导出与偏好为明确的次级入口；
不把全部菜单平铺在工具栏。正在使用输入法时减少底部常驻导航，保留完成编辑和标签导航。

### 5.2 紧凑宽度（手机及窄分屏）

```text
返回   工程名 / 保存状态        撤销 重做 更多
页码与缩略图入口                 分组筛选
------------------------------------------------
                  图像画布
       marker / 选区 / 缩放复位按钮
------------------------------------------------
当前 #标签  分组  批注数       上一条 下一条
         可展开的标签列表 / 文本编辑面板
------------------------------------------------
               编辑    校对    页面
```

底部面板有折叠、半屏、全屏三档；默认折叠显示当前标签摘要，点编辑后展开并唤起输入法。
拖动把手只改变面板，不与内部文字选择或列表滚动争抢；长文可全屏编辑并提供一键返回图像。
画布保留可见时，面板改变大小只按几何锚点恢复视口，不因标签同步重新聚焦。
手机横屏且高度不足时不强行三段布局，优先画布/编辑二者切换。

### 5.3 宽窗口（平板、折叠屏展开）

左图右文，右侧含虚拟化标签列表与当前文本/批注面板；页面缩略图按需展开，不常驻第三侧栏。
双栏初始约 60:40，可拖动；最小宽度由控件隐式尺寸、字体和触控目标推导，不能压出重叠控件。
按实际可用宽高而不是设备型号判断；建议从 840 逻辑单位开始尝试双栏，两侧最小尺寸不足则退回单栏。
阈值是初始设计值，须测量 Qt 逻辑坐标与 Android 密度映射；切换加入滞回，避免键盘出现时布局来回跳。
布局切换不新建文档/撤销栈、不丢选择、不重设比例；折叠铰链不覆盖操作控件。

### 5.4 视觉与可达性

使用 Qt Quick Controls 的一致移动样式，跟随浅/深色；不移植 Breeze QSS，不追求像素级复刻 KDE。
图像是主体，工具栏紧凑、层级清楚，不使用装饰卡片嵌套。选中态、错误和待确认态同时有文字/图标，
不只靠红绿区分。触控目标以约 48 dp 为初始目标，视觉 marker 可以更小但命中范围单独处理。
字体跟随系统设置并允许应用内调整；长页名省略但可查看完整名称，正文不省略不可访问。
所有图标有可访问名称；TalkBack 可从标签列表完成选择、编辑、删除和定位，不要求精确点击画布。
适配系统边缘返回、状态栏、导航栏、挖孔和输入法 inset，不用隐藏系统导航换取布局空间。

## 6. 手势与选择状态机

### 6.1 明确模式

画布常驻工具提供“浏览 / 添加 / 移动 / 选区”。默认浏览；多选是选择状态，不再隐式改变工具。
操作只能通过一个手势仲裁器产生语义命令，不由多个 MouseArea/TapHandler 各自抢事件后修改工程。

| 输入 | 浏览 | 添加 | 移动 | 选区 |
| --- | --- | --- | --- | --- |
| 点 marker | 选择并显示摘要 | 选择，不新增重叠标签 | 选择移动目标 | 不改标签，选区工具优先 |
| 点空白 | 清除单选，不改内容 | 在图像内新增一个，进入文本编辑 | 清除选择 | 开始/调整选区 |
| 单指拖动 | 平移画布，包括从 marker 起拖 | 平移，不新增 | 从已选 marker 起拖预览移动；空白仍平移 | 图像内创建/调整矩形 |
| 双指拖动/捏合 | 平移/缩放 | 平移/缩放 | 平移/缩放，不移动标签 | 平移/缩放，选区仍绑定图像坐标 |
| 长按 marker/列表项 | 进入多选并选中该项 | 取消添加意图并进入多选 | 不直接删除 | 无标签操作 |

添加默认一次完成后退回浏览，重复添加可由明确的持续模式开关启用。取消空标签编辑时询问是否移除，
不能无声保留或删掉用户有意创建的空标签。浏览模式双击图像缩放；marker 编辑用面板按钮，
不让双击新增/打开编辑器/缩放三个动作竞争同一位置。

多选由逐项点选、全选可见、清空和列表区间选择完成；不依赖 Shift。上一次选择锚点必须仍可见有效。
分组筛选隐藏的 Label 从选择中移除，零选中绝不代表全部；标签多选限定当前页，翻页清理。
点 marker 同步列表但不移动画面焦点；修订交互下从列表明确点选才定位画布。删除、撤销、程序刷新不聚焦。
手机不模拟 hover；鼠标 hover 只是可选预览，不产生额外自动选择竞争。

### 6.2 拖动、取消与冲突

- 按系统/平台统一的拖动和长按阈值仲裁；手指移动超过阈值后不能再识别为点按或长按。
- marker 视觉小但命中区扩大。多个命中区重叠时显示候选标签选择，不悄悄选中另一项。
- 拖动期间只更新临时显示，释放时通过 LabelEditController 提交一次撤销命令；取消还原预览。
- 第二根手指加入、系统取消、来电/退后台、旋转、页面切换时取消未提交拖动，再进入适当的视图手势。
- 移动多选保持相对偏移，整体位移限制在合法范围，不逐个截断造成标签相互挤叠；边界外不新增标签。
- 手势抓取、缩放中心与归一化坐标计算集中管理。解码分辨率变化不改变 marker 坐标；禁止隐式旋转图源方向。
- 删除只能来自明确命令。单项删除可直接撤销，批量删除显示数量确认；不采用“长按即删”或滑动即永久删。
- 选区截图坐标映射到原图，不能直接截屏夹带悬浮控件；大图按区域预算输出，不能为一张截图无限解码。

键盘快捷键复用 AppPreferences/命令路由，编辑框里的复制粘贴/撤销保持文本作用域；
鼠标右键在移动端打开操作菜单，不沿用桌面“右键立即删”作为手机默认。触控笔不假设具备 hover 或侧键。

## 7. 文本输入、返回与恢复

### 7.1 编辑事务

文本编辑会话以 documentSession、页面/Label UUID、起始文本版本绑定，不缓存容器地址或行号。
QML TextArea 是输入载体，不持有第二份长期工程模型。文本草稿保留光标、选择及滚动位置；
同标签一次连续编辑按现有合并规则形成撤销单元，不每个拼音键提交一次标签命令。

中文/日文 IME 预编辑文本不进入 Label 正文和 diff。切换标签、保存、导出、完成校对前请求输入法提交，
等待实际文本提交事件后再执行后续命令；不能以一个零延时定时器假定组合输入结束。
恢复只能保证已提交的输入文本和落盘草稿，不承诺恢复被系统终止时输入法内部的未提交候选。
Label 已被删除、会话已替换或基准版本改变时，保留孤立草稿供复制/恢复，不能覆盖新对象。

### 7.2 返回顺序

系统返回按可取消的当前上下文处理：输入法 → 当前弹层 → 未提交的工具/多选状态 → 子页面 → 工程列表。
普通编辑退回前提交或保留草稿；页面管理/设置等未应用草稿询问“应用 / 保留草稿并离开 / 丢弃”。
事务提交关键阶段返回仅提示正在完成，不销毁拥有事务的对象；取消已请求不代表已回滚完成。
预测性返回手势取消时不得提前执行删除、保存或丢弃。再次退出应用不要求用户必须导出，但应保留交接状态。

### 7.3 本机保护与进程终止

持续进行有界、原子的草稿检查点，初始目标为输入停顿 1 秒后保护、持续输入最多约 5 秒调度一次；
这不是系统强杀下的零丢字承诺。活动工程自动保存与草稿保护有独立状态，不把二者都当正式保存。
仅把完成持久化的版本显示为受保护。退后台尽快处理已提交文本与最近检查点，但不依赖退出回调。
Android 可能终止进程，`onDestroy` 不保证调用，见 [进程生命周期](https://developer.android.com/guide/components/activities/process-lifecycle)。

启动先回放/诊断未完成文件事务，再恢复最后有效文档，再验证文本和页面管理草稿；损坏草稿保留待人工处理。
正常旋转只重排视图；进程重建重新安装文档与新会话，旧回调全部作废。重启不恢复 QUndoCommand 闭包，
但保留恢复记录并提示撤销历史已重置。自动保存不会因“已保存”清空正常撤销栈。
数据与敏感 URI 的系统自动备份/设备迁移策略需显式配置，不能默认把整套图源上传系统云备份。

## 8. 校对、页面管理与其他功能联动

### 8.1 校对布局

校对入口展示轮次状态、“开始/完成本轮”“查看变更”“批注”；危险的清除记录放二级菜单。
批注按当前标签/页面及全部查看，失联项有专门筛选与重新关联入口，禁止凭行号猜归属。
手机 diff 为变更列表 → 详情；详情固定文本 diff 与当前/目标图切换，左右方向和绿色新增语义沿用桌面。
平板可并排显示双图；同步缩放必须显式开关，只同步归一化视口，不假设两图尺寸相同。

筛选采用底部面板：页面、变更、摘要、审阅状态多选。全选/清空不关面板，应用时保留当前项 UUID，
若被过滤则清空详情。摘要多属性取并集，不同筛选维度取交集；格式/文字分类复用原服务。
审阅状态保留彩色图标与文字，点击条目不自动“已查看”；批注解决与审阅状态独立。
长文本虚拟化/分段显示但可完整展开和复制，不能截断结果再用于 HTML。
正文、批注和文件名一律按纯文本处理；显示 diff 的富文本只能来自共用的转义渲染器，不能把外部字符串
作为 QML/JavaScript 或可执行 HTML 注入。首版不为报告预览引入任意 WebView 脚本执行。

完成轮次前提交当前编辑器并验证版本；已完成文本冻结、批注身份和后续页面操作规则与桌面一致。
外部比较导入只读副本；若正文变化使结果过期，显示“重新计算”，禁止将旧审阅提交到新版本。
只读预览可以保留旧快照供查看，但导出需明确版本，不悄悄输出与当前显示不同的数据。

### 8.2 页面管理

手机使用行列表，每行有缩略图、当前图片、待应用目标、输入预览/错误、原页序；点行展开详细内容。
平板可使用同一模型的多列视图，不维护两份 pending。
长按/工具栏进入多选，拖动使用专用把手；排序也提供“上移/下移/移到位置”，避免长列表只能拖放。
处于筛选状态不允许拖动重排，仍可选择与预览；全选仅指明确标示范围，零选中不扩展为全工程。

格式串继续只支持 `{index}`、`{index:03}`、`{stem}` 等当前 DSL 规则；高亮、合法性、扩展名保护和
命名冲突由共用解析/规划服务给出，QML 不重新写正则解析器。
起始序号可以为 0 或 1，也可输入合法整数；选中子集按当前页序编号，不按用户点选先后编号。
“加入待处理”累计到按页身份绑定的草稿，改变选择、格式或页序都不清空 pending。
缺图指定/匹配时先将候选复制至草稿暂存区并立即预览；确认提交才安装为工作区图片，失败保留草稿。
已存在图源的改名与缺图引用修复要在同一计划中校验目标碰撞，不靠 UI 把错误隐藏。

按“应用并返回”先显示数量/影响确认，再执行前置保存、文件事务和最终保存；全部成功才关闭页面。
纯页序操作保持普通撤销；包含文件/引用操作时遵守原清空撤销确认规则。失败不得发布半份工程。
页面移除不直接删除图片；图片可能被校对快照或恢复记录引用。清理未引用资源是独立维护流程，首版不自动清理。

### 8.3 联动约束

| 场景 | 必须保持的行为 |
| --- | --- |
| 进行中/完成校对后改名、重排、缺图修复 | 页/Label 身份稳定；快照文本与批注不被重建，路径通过共用服务迁移 |
| 合并两个来源工程 | 新输出身份按合并规则产生，不继承任一来源的活动轮次；输入只读 |
| 替换预览后再改文本或页序 | 原指纹不再有效，重新预览后才可提交 |
| 工作区恢复/重新导入替换活动文档 | 通过统一 adopt 入口刷新会话，清理旧撤销、旧异步结果和编辑绑定 |
| 同一工程文件被再次从 QQ 收到 | 不因 project UUID 相同覆盖工作区，询问打开、导入副本或比较 |
| 页面草稿期间收到新包、发生保存错误 | 延后切换；不销毁草稿、不自动覆盖外部包 |
| 分享后继续编辑 | 已生成文件不可变，新的改动显示未导出；重新分享需选择旧包或生成新版 |
| 外部 LabelPlus 改写了 metadata/正文 | 沿用身份校验及降级，不把失联批注关联到同序号新标签 |

## 9. 技术架构与重构边界

以下名称是拟定职责，不是要求一次性创建所有类或目录。提取真实共用规则后再定最小 API。

```text
桌面 Widgets                 移动 QML
现有 UI 控制器               薄 QObject/Model 适配
             共用文档/编辑/校对/页面规划服务
             共用 Core、身份、版本与撤销
本地文件事务             工作区 + 导入导出协调
                         Android URI/Intent/JNI 桥接
```

- `src/core` 不依赖 Widgets、Quick、JNI；保留 Qt Core/Gui 等必要基础依赖，不为“纯 C++”重写 QUndoStack。
- `src/services` 提取可共用的工作流；Qt 控件展示不进入业务服务，平台桥接不进入文本格式层。
- 现有 `src/ui` 继续承载桌面；拟新增 `src/mobile`（QML、移动呈现模型）、`src/platform/android`
  （URI、生命周期、分享桥接）及 `android/`（Manifest、Java/Kotlin、打包资源）。
- JNI 输入转换为值类型请求，返回通过队列投递到 owner thread；不将活动 Project 裸指针交给 Java 或 worker。
- `ProjectStorage` 一类接口若需要，只描述来源读取/导出能力；首版本地工作区依然走现有文件事务。
  不把所有 QFile 调用包成虚拟接口，也不伪造“所有 URI 都支持原子 rename”。
- `WorkspaceService` 管本机清单、持久副本和恢复；`ProjectTransferService` 管导入/导出计划及状态；
  `ArchiveService` 只管有界归档；Android 桥接只管获取流/授权/启动系统 UI，彼此不接管正文编辑。
- 单个“MobileController”不能承担工程、页面、校对、文件、键盘、分享全部状态；按现有领域分工。

### 9.1 现有 UI 控制器如何复用

不能让 QML 为了复用而创建隐藏 QWidget，也不能复制桌面控制器再逐个修 Android 分支。

| 现有边界 | 移动化策略 |
| --- | --- |
| LabelEditController / ReviewRoundEditService | 直接作为共用命令入口；补显示适配，不另开 mutation 路径 |
| CurrentPageLabelContext / LabelSelectionController | 提取身份、可见集合、选择来源规则；Widgets/QML 分别绑定控件 |
| ImagePageViewController | 提取加载代次、缓存和视口恢复协调；具体 QGraphicsView/QQuickItem 操作各留适配器 |
| EditorStateController | 提取编辑会话/提交/恢复规则；Widget 焦点检测和 QML IME 细节分离 |
| ProofreadingController / BackgroundTask | 保留业务快照与取消规则，提取不依赖忙碌对话框的任务协调 |
| PageOrderListModel / ProofreadChangeTableModel | 优先复用数据和筛选模型；补 QML role 或薄代理，不复制业务数组 |

抽取时让桌面也调用共用实现，并以现有回归验证。不为将来可能出现的平台发明通用状态机框架。
状态采用明确枚举和合法转换；少量有名的工作流状态胜过散落的 busy/closing/restoring 布尔量。

### 9.2 构建与依赖

第一步拆分可链接的 Core/Services、Desktop、Mobile 目标，源文件仍显式列出，不改为全目录递归 GLOB。
根据目标查找 Widgets 或 Qml/Quick/QuickControls2；移动版不因关闭自动化仍强制 find QtKeychain。
Python runner、协议 UI 与任务底座分别切分，保留身份、字段版本、统一提交及桌面自动化测试。

拟增加 Android ARM64 开发/发行 preset，x86_64 用于模拟器；名称和命令在实际实现后才写成可执行教程。
M0 锁定 Qt 补丁版、NDK、SDK、JDK、Gradle/AGP 和宿主工具版本；验证标准库的 C++23 能力，
不能通过局部降为 C++17 或引入第二套 expected 回避工具链问题。最低 Android 版本随选定 Qt 支持矩阵
和测试设备确定，不在尚未构建时承诺特定版本。工具链依据：[Qt Android 入门](https://doc.qt.io/qt-6/android-getting-started.html)。

应用资源走 qrc/Android 资源，偏好写 AppConfigLocation；移动端不复制可执行文件旁的 preference/scripts。
先发布签名 ARM64 APK 供内测；商店 AAB 是后续渠道，不以安装成功替代商店政策审核。
原生 Qt/归档/zlib/图片插件均检查 ABI、16 KiB 页兼容与设备加载，不能只测主库。
依据：[Android 16 KiB 页大小](https://developer.android.com/guide/practices/page-sizes)。

发布使用受审查的 Qt 动态依赖方案，核对实际 APK 模块、许可、源码获取与修改后重构建/重打包说明；
不能把“在 APK 中是 .so”当作已经满足全部许可义务。Quick Controls 的许可需按选定版本复核，
当前官方说明列出 LGPLv3 等选项：[许可说明](https://doc.qt.io/qt-6/qtquickcontrols-index.html#license-and-attributions)。
系统输入法即可，不为软键盘引入 Qt Virtual Keyboard；禁止未审查的 GPL-only 模块。签名密钥不入库。

## 10. 异步、并发与性能

主线程拥有活动工程、撤销栈、选择和编辑会话；worker 只处理不可变快照、图片字节和封装后的文件操作。
回调校验 documentSession、请求代次与资源版本；页面卸载/旋转/工程关闭不能让旧结果访问新模型。
文件工作流的协调属于服务，不在 QML 里靠禁用按钮保证安全；后台与代码调用也必须执行同一检查。

| 任务 | 允许并行 | 受保护/拒绝操作 |
| --- | --- | --- |
| 图像加载、搜索、diff | 普通编辑 | 过期结果不得安装/提交 |
| 接收 QQ 输入/扫描暂存包 | 当前工程普通编辑 | 暂存就绪前不能成为活动工程 |
| 导出快照、复制图源 | 正文编辑可继续，导出版本固定 | 暂存图源完成前阻止相关文件改名、工作区删除和替换 |
| 包生成/分享已暂存产物 | 所有不涉及该产物的编辑 | 产物不可变，不能清理仍被服务使用的文件 |
| 页面文件事务、恢复 | 可查看进度和只读内容 | 当前工作区写入及会话切换；取消到安全点才返回 |

锁/租约按资源和工作流表达，遵循固定获取次序，不持锁等待用户确认。只读的长任务可以取消；
进入文件提交关键阶段显示“正在完成”，不能把 UI 隐藏等同于 worker 停止。
本机保存串行化并合并排队请求；快照的序列化与最终版本确认分开，禁止旧保存结果覆盖新磁盘版本。
自动保存、手动保存、页面事务、导出必须共用写入协调，不各自引入 QSaveFile 写活动 TXT。

图片缓存改为字节预算并限制并发，预览按显示尺寸解码；保持原始尺寸用于归一化坐标，不重新编码图源。
低内存时释放相邻页/隐藏预览，保留必要编辑数据。纹理上传也计入预算，不能只计算 QImage。
分辨率分级必须有正确的缓存 key，不能沿用仅路径 key 后把缩略图当原图；EXIF 方向与桌面保持一致。
主图、diff 双图、合并图共享有界调度；超大图无法安全解码时允许继续文本编辑并提示，不尝试解码到 OOM。
是否引入分块解码由 M0/M2 数据决定，不能以更换 QML Image 就宣称解决长图问题。

文本 diff 必须继续走 TextDiffService。已知 diff-match-patch cleanup 路径的堆破坏风险不会因为换成
Android 自动消失；保留现有门控，增加中日英混合文本、Unicode 随机输入及差异重建测试，结合宿主
ASan/UBSan 与目标设备回归。不得绕过门控换取视觉一致，也不能把 CJK 比例阈值当作完整安全证明；
若移动移植验证中复现内存破坏，作为发布阻断处理，共用修复同时回归桌面。

## 11. Corner case 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| QQ 冷启动/热启动/重复 Intent/缺读权限 | 正常接收或可解释失败；不重置当前工程、不产生重复写会话 |
| QQ 分享面板取消、离线、切回应用、目标延迟读取 | 产物仍可重试，不报告发送成功，不提前删文件 |
| ZIP 不可 seek、长度未知、被截断、CRC 错误 | 有界暂存后验证；失败不发布工程 |
| ZIP 路径穿越、链接、重复项、ZIP bomb、恶意文件名 | 提取前/中拒绝，不写暂存根外、不耗尽无限资源 |
| ZIP 多个 TXT、嵌套目录、GBK 名称、同名大小写碰撞 | 显式选择/诊断，不猜工程或静默覆盖 |
| 仅 TXT、全部缺图、零 Label、空页面 | 可打开正文并修复，不因预览为空 crash |
| 源 URI 权限撤销、文件移动、云提供者离线 | 已导入工作区可继续；再次导入要求重选，不偷偷覆盖 |
| 私有图源路径指向包外或设备系统文件 | 拒绝解析到根外，显示缺图 |
| 导入/保存/导出/改名各阶段磁盘满或进程终止 | 保留最近有效工程与恢复证据，失败不清 dirty、不发布半计划 |
| 打包与改名同时请求、恢复与自动保存并发 | 服务层协调；不生成 TXT 与图片名错位的包 |
| 同工程多副本/不同工程同名、再次收到校对稿 | 工作区身份隔离，可显式比较，不自动合并 |
| IME 预编辑时点保存/切标签/导出/返回 | 先处理真实提交，不丢字、不将拼音候选当正文 |
| 编辑目标删除/重载、旧 worker 迟到 | 草稿保留待处理，旧结果拒绝，不能写到同序号新标签 |
| marker 重叠、第二指加入、越界拖动、系统手势中断 | 无误删/误新增；取消预览，无额外撤销记录 |
| 筛选全清/隐藏当前项、页序变化后选择恢复 | 选择按有效身份恢复，零选中不扩大操作范围 |
| 旋转、折叠、分屏、键盘弹出、字体放大 | 内容与视口锚点稳定，按钮不重叠，编辑会话不重建 |
| 完成校对后改名/删页、外部修改身份失配 | 冻结结果不变，批注不误关联，缺历史图明确提示 |
| 图片损坏、超大长图、低内存、解码中关工程 | 可解释降级，不留悬空 UI 指针，不把失败当空图成功 |
| 分享 TXT 到原版、ZIP 解压到 Windows/Linux | 正文、页名、扩展名对应，私有路径不泄漏 |
| 更新 APK、系统恢复、卸载/清数据 | 正常升级保留工作区；schema 不兼容不覆盖，删除风险有说明 |

## 12. 分阶段实施与门槛

每阶段交付测试与文档，不允许先堆 UI 再补持久化。下面步骤有依赖，不是并行修改同一大控制器的任务清单。

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 技术验证 | 固定工具链；最小 QML/IME/图像/文件选择/QQ 收发探针；归档与许可验证 | 真机收发普通 ZIP、ARM64 加载、C++23 和输入法通过；记录未支持设备/QQ 情况 |
| M1 共用底座与工作区 | CMake 库目标；平台桥接；安全导入、ZIP 导出、本机保存/草稿/恢复 | 故障注入和桌面回归通过；URI 不进入本地事务；旧自动化仍可用 |
| M2 日常编辑 | 响应式布局、手势状态机、Label/分组/选区/撤销、搜索替换、缺图提示 | 手机及平板完整完成导入→编辑→QQ 分享→桌面打开 |
| M3 完整业务 | 校对轮次/批注/diff/HTML、合并、页面管理/改名/修复、偏好 | 第 2 节保留功能逐项验收，跨功能矩阵通过 |
| M4 发布收敛 | 真机稳定性、升级恢复、性能/无障碍、签名/许可/手册/演示图 | 发布检查清单齐全，无未解决的 crash/丢稿/错误覆盖高风险 |

M0 的 Qt/NDK 版本、最低系统、归档库裁剪方案和性能预算必须形成记录；验证不成立时更新方案，不把实验结论伪装为支持承诺。
时间估计仅用于排期：熟悉 Qt 的单人全职投入，M0 约 1～2 周，M1/M2 达到基本可用约 1～2 个月，
完成 M3/M4 约 3～6 个月或更长；资源、安全和设备兼容结果会改变排期。

## 13. 协作与文档同步

公共约定同步写入 [AGENTS.md](../AGENTS.md) 和 [CONTRIBUTING.md](../CONTRIBUTING.md)，实施者必须先读本文。
桌面 UI 专属规则不能直接当移动 UI API，但其中的业务不变量必须在抽取后继续共享。

每个实现 PR/commit 应说明：所属阶段、共用边界、桌面行为是否改变、失败/取消/进程终止语义、
测试证据与尚未验证的真机条件。跨模块改动先提取共用规则，再接平台适配；不堆 Q_OS_ANDROID 分支到 MainWindow。
新增第三方依赖时同步依赖文档/声明，新增角色/模型时同步测试，新增构建目标时同步 devtool 模块路由与 preset 教程。

移动 C++ 文案用 `tr()`，QML 用 `qsTr()`/`qsTranslate()`，共用服务文本避免复制翻译上下文。
在第一个 QML 功能引入时扩展四语言提取和检查工具；当前仅 C++ 检查通过不代表 QML 已覆盖。
可配置交互进入 AppPreferences/默认值；移动布局会话与工作区状态留在本机存储，不写入工程 metadata。

用户手册增加 Android 操作章节后才宣称支持：须讲清导入副本、应用内保存、QQ 交接、卸载风险、
缺图修复、备份恢复以及不支持项。截图标明 Android/设备，不用 Fedora 截图假装移动版；桌面手册保持准确。
本文不是新增无限历史、云同步、OCR、任意外部写入或后台常驻任务的授权。扩大范围先更新设计和验收边界。
