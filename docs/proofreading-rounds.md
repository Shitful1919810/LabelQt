# 校对轮次与批注（第一版）

## 用户流程

编辑 → 校对 → 开始校对，保存本轮原译稿。之后直接编辑文本、分组、marker、标签或页面；
“修订交互”单独控制 marker 悬停联动，不开启或清除记录。

右侧文本编辑区下方的“校对批注”可展开。加号添加当前 Label 的批注，工具菜单可添加页面批注。
双击批注编辑；工具菜单可解决/重新打开、跳转、删除或明确关联到当前选中的 Label。
默认显示当前 Label 及当前页批注，“全部批注”用于查看全工程及待重新关联项。
列表序号旁的图标表示存在批注，未解决与全部解决使用不同颜色及提示。

“查看校对变更”包含实际差异和仅有批注的项目。页面、变更类型、摘要与审阅状态筛选取交集；
HTML 导出使用相同结果，包含纯批注项。已查看是对某个差异版本的阅读状态，不等于批注已解决。

“完成本轮校对”确认后固定原译稿、完成稿和批注正文，后续普通编辑不改变已完成的文本差异。
仍可更新审阅状态、解决状态，以及批注跳转目标；重新关联不改写已完成报告的文字归属。
“清除校对记录”是单独的确认操作，只删除本轮记录，保留当前译文。
第一版只保留一轮；开始下一轮前提示导出旧报告，确认后替换。不自动保存无限历史。
这些操作均属于普通撤销，最后仍需正常保存 TXT。

## 数据与职责

- `ReviewRoundService`：轮次及批注的数据编解码、旧基线读取、净差异与批注的组合、当前跳转定位。
- `ReviewRoundEditService`：主线程、版本约束的统一提交，以及只修改所属 metadata section 的撤销重做。
- `ProjectComparisonService`：页匹配与比较计划；`LabelSequenceDiffService`：Label 对应关系与顺序判定。
- `ProofreadingController`：菜单、确认和模态输入编排，不修改正文；`ProofreadNotesWidget` 只缓存轻量展示行。
- `ProofreadChangesDialog`、`ProofreadChangeTableModel` 和 `ProofreadReportService` 共用 `ReviewChange`，
  `Comment` 表示无正文变化的批注项，`noteText` 是已本地化的纯文本，不作为 HTML 执行。

`LabelQtMetadata.proofreading` v1 包含轮次 UUID、`before`、可选 `after`、独立批注数组和审阅 `session`。
快照保存页面/Label/分组身份、文本、坐标、顺序和图片引用；不包含工程注释或另一个轮次，避免递归膨胀。
空页面也会保留。软删除 Label 不进入快照，跳转以 UUID 为准，不依赖保存前后可能变化的数组下标。
图片不复制到 TXT：预览优先按页面 UUID 使用当前有效图片路径，不承诺保存旧图片的像素内容。
跨目录另存/备份/恢复由 `ProjectLocationService` 统一重定位快照引用，历史页名不被重命名操作覆盖。

批注拥有独立 UUID、页面/Label UUID、创建时页名、文字摘录、正文和解决状态。
页面级批注没有 Label UUID。显式重新关联的目标与原始归属分开；完成时固定当时已经确认的归属。
不以 diff 行号或变更指纹保存批注。审阅状态仍按差异指纹保存，文字继续变化时不自动继承已查看。

旧 `review` 基线与 `reviewSession` 可以读取。首次提交轮次操作时迁入新 section，保留原译稿及旧审阅数据；
旧基线没有可信身份，仍用启发式匹配，过期审阅指纹不会被强行套用。新轮次结果不提供人工配对入口；
独立的外部工程对比继续支持人工配对和本机审阅会话。第一版不提供字符范围批注、回复线程或多人权限。

## 身份与外部修改

同一工程且页面 UUID 对应时，优先按页面身份匹配。`ImageEntry::labelIdentityGeneration` 在正常编辑、
重排、改名和保存时保留；外部正文签名不符时，页面 UUID 可保留，但 Label UUID 与身份代次重新生成。
旧身份 metadata 没有此字段时，用已验证的页面 UUID 作为代次，保持旧文件可读。

身份代次一致时按 Label UUID 配对。文本大幅改写仍是修改，删除后新建相同文本仍是删除加新增；
仅因插入或删除造成的行号偏移不标记为移动，只有相对顺序反转才标记移动。
代次不符时使用原序列匹配并提示；批注不自动附到推测出来的新身份。失联批注保留文字摘录与警示，
用户可以在“全部批注”中确认新目标。页面 UUID 消失时不凭同名页面恢复批注或跳转。

无效或不支持版本的轮次保留原始 metadata，显示记录不可用，不阻止正文的正常查看。
记录读取失败不被解释为“没有轮次”，不得以新空记录静默覆盖。

## 与其他工作流的联动

| 工作流 | 行为 |
| --- | --- |
| 自动化、全文替换、普通编辑 | 继续经现有编辑入口修改正文；进行中轮次派生最新差异，完成稿不变 |
| 脚本读取 metadata | 校对提交推进 Metadata 版本，依赖旧 metadata 的结果拒绝提交；无此依赖的合法文本任务不因批注变化而失效 |
| 模态确认/批注输入期间有其他提交 | 校对提交同时检查任务会话与工程版本，不把旧对话框草稿覆盖到新状态 |
| 外部 TXT 变化 | 继续由既有监听与恢复流程询问；重载后重读轮次，正文失配则降级身份，不自动合并本地批注 |
| 页面重排、移除、文件改名、修复引用 | 沿用页面身份；不清空轮次或批注；文件事务、前后保存与清空普通撤销的规则不变 |
| 完成后继续改 Label/页面 | 完成稿差异冻结；跳转定位当前身份，Label 不在时最多跳到仍存在的页，不跳到旧序号上的其他文字 |
| 另存、备份、恢复 | 复用单 TXT 持久化和冲突检测；快照图片引用一起重定位 |
| 合并工程 | 沿用现有规则生成新工程和新身份，不把某个输入工程的校对轮次冒充为合并结果的轮次 |

`ProjectController::documentSession` 只在打开/替换文档时变化，用于隔离撤销回放；
另存仍使自动化任务会话失效，但不使同一文档的普通撤销失效。UI 不长期持有活动 Project 的容器副本。

## 兼容与验证

TXT 正文仍是当前有效译文、坐标和分组，不添加伪标签或批注文字。私有记录放在原有压缩注释块，
不是加密。总 metadata 继续受 32 MiB 解压大小限制；超限先报错，不应用半份记录。
批注最多 10000 条，单条正文最多 65536 个 UTF-16 代码单元，摘录最多 1048576 个。
原版 LabelPlus 不显示这些增强信息，交接给原版用户时可以同时导出 HTML。
外部软件删除或重写私有注释可能丢失增强信息；未声称对所有原版版本实测无损往返。

`ReviewRoundTests` 覆盖快照/正文分离、精确身份匹配、完成后继续修改、纯批注筛选与报告转义、
外部编辑身份降级、自动化依赖、过期/跨线程提交、另存撤销、异常记录和旧基线迁移。
原版 LabelPlus、Windows 原生样式和大型真实工程仍应在发布前进行人工往返与体验验收。
