# Android 技术预览使用说明

本文介绍当前已经可用的移动版，不是未来功能清单。适用于 Android 9 及以上的 ARM64 设备；
手机和宽屏设备使用不同布局。当前 APK 为技术预览，重要工程请保留外部备份。
构建与安装见 [Android 构建](android-build.md)，后续范围见 [移植方案](android-port-plan.md)。

## 先了解数据保存在哪里

整个流程是：**导入工程包或原图包 → 编辑本地副本 → 保存 → 分享新的 ZIP**。

- 导入不会修改 QQ 下载的原文件；重复导入同一个包会建立独立副本。
- “保存”只更新应用内的工程，不会更新原 ZIP，也不会自动发送给别人。
- “分享 ZIP”生成当时工程的快照；继续编辑后，需要再次分享才能交付新内容。
- 卸载应用或清除应用数据会删除本地工程。操作前先导出正文和图源并确认外部副本可用；
  校对记录不随 ZIP 导出，需要保留这些记录时不要清除本地工程。

## 导入工程

1. 准备工程压缩包（一个 LabelPlus TXT 和引用的图片），或者仅包含原图的压缩包，保留相对目录。
2. 打开应用，在首页点击“导入压缩包或 TXT”，通过系统文件选择器选择文件。
3. 导入完成后，在“本地工程”列表中打开工程。

例如，TXT 中引用 `001.jpg`、`002.jpg` 时，可以这样组织：

```text
作品.zip
└── 作品/
    ├── 翻译.txt
    ├── 001.jpg
    └── 002.jpg
```

图片必须位于 TXT 所在目录或其子目录内，且与 TXT 中的引用一致。
支持 ZIP、7z、RAR/RAR5、tar、tar.gz（含 `.tgz`），按文件内容识别，不仅看扩展名。
ZIP 仍要求 UTF-8 文件名、store/deflate 压缩，不支持 ZIP64。
当前不支持加密、分卷、自解压程序，也不会继续解开嵌套压缩包；部分特殊压缩方法可能不受支持。
tar.gz 要求单个 gzip 数据流，校验 CRC 和长度；拼接多个 gzip 文件的包不支持。

一个包最多只能有一个 TXT，说明用的 `README.txt` 应移出压缩包。
有 TXT 时以该工程为准；TXT 损坏不会自动退回“新建工程”，避免误丢已有译文。
macOS 自动附带的 `__MACOSX` 目录和 `._` 开头的资源文件不参与工程或图片页识别。

### 用原图包新建工程

没有 TXT、只有图片时，导入会自动创建空白工程，无需先在电脑上建立译稿。
它递归收集当前图片插件支持的文件（如 JPG、PNG、WebP），按相对路径自然排序，
例如 `2.jpg` 在 `10.jpg` 前；子目录会保留，两个目录内的同名图片不会合并。
新工程使用与桌面一致的默认分组，进入后可直接添加标签和输入译文。
不能读取头部的图片会报错，不会静默跳过缺页；其他非图片文件不进入新工程。
压缩包内的图片都作为页面，不自动识别封面、广告或多章节；目前手机仍不提供页面重排入口。
每次选择一个包，多个包分别导入为独立工程，不自动拼接成一部作品。

单独导入 TXT 不会获得读取相邻图片的权限，因此可能只有文字而没有图像。手机上优先导入完整 ZIP。
缺图工程目前不能在手机中补图，请先在桌面修复并重新打包。

**从 QQ 接收：**先下载文件，再尝试“用其他应用打开”并选择 LabelQt。
若 QQ 没有提供该入口，可保存到系统文件选择器能访问的位置，再回到 LabelQt 导入。
不同手机的文件选择器入口可能不同，可从其侧栏选择“下载”等位置；“最近使用”为空不等于没有文件。
不需要开启“全部文件访问权限”，应用也不会扫描 QQ 的私有目录。

## 管理本地工程

首页直接显示工程列表；进入工程后，左上角按钮可打开同一列表。
列表抽屉可用右上角关闭按钮、点击外侧或返回键关闭。

| 操作或信息 | 含义 |
| --- | --- |
| 工程名称 | 新导入时采用压缩包名称去掉扩展名（`.tar.gz` 整体去掉）；不是内部 TXT 的名称 |
| 灰色“最近编辑”时间 | 工程 TXT 最近成功保存的时间，不是最近打开时间 |
| 条目右侧菜单 → 重命名工程 | 只修改列表显示名，不改 TXT、图片或原 ZIP 的文件名 |
| 条目右侧菜单 → 删除工程 | 确认后删除本地副本及其图片，不可撤销；原导入文件和已生成的分享包保留 |

重命名列表中的工程不会改变根据原压缩包名生成的默认分享名。分享文件名可以单独修改。

## 浏览与编辑

手机通过“图像”“标签”“校对”切换视图；宽屏下图像和标签列表可并排显示。
上方页码选择框和左右箭头用于翻页。

| 目的 | 操作 |
| --- | --- |
| 移动画面 | “浏览”模式下单指拖动空白处 |
| 缩放 | 双指捏合；“浏览”模式双击空白处也可切换缩放 |
| 显示整张图片 | 点击画布工具栏的“适应窗口”图标；它不是全屏开关 |
| 选中标签 | 点击图中的编号标记，或“标签”页中的文本条目 |
| 选择重叠标记 | 点击重叠区域后，从候选列表选择 |
| 添加标签 | 切到“添加”，点击图像空白处，再编辑文本 |
| 移动标记 | 先选中标签，再在“移动”模式拖动该标记 |
| 取消选择 | 在“浏览”模式点击空白处 |
| 删除标签 | 选中后点击底部垃圾桶按钮并确认；可撤销 |
| 撤销、重做 | 顶部两个箭头按钮；历史仅保留在当前打开会话中 |

两指缩放结束时，请先抬起所有手指，再开始新的单指操作。
移动模式下拖动未选中的标记不会移动该标签，需先点选。

选中标签后，底部可修改文本和分组。点击文本框开始输入时，界面会收起部分导航控件，
保留图像和可滚动的编辑区；长文本在编辑区内滚动。点击顶部键盘图标结束编辑并收起输入法。

右上角工程菜单中的“分组”可筛选显示范围，也可新增分组。筛选同时影响图像标记和标签列表，
不会删除标签。添加标签时使用当前可见分组中按工程顺序排列的第一个分组；没有可见分组时不能添加。
可在添加后通过底部分组框修改所属分组。
分组名不能重复、为空或包含换行，单独的 `-` 是保留名称。输入无效时会保留输入并提示，不会新增分组。
不同分组用颜色/形状区分，选中时增加外圈；筛选不会重新分配颜色。
移动版尚无完整的样式偏好设置界面。

标签编号与桌面版一致，按当前可见标签从 1 连续排列：删除 2 号后，原 3 号显示为 2 号；
筛选分组也会重新排列显示编号。编号变化不影响标签内容或已有批注。
保存和分享始终包含全部未删除标签，不会漏掉被筛选隐藏的标签。

## 保存与撤销

编辑后会延迟自动保存；切换工程、分享前会先保存，进入后台时也会尝试提交输入并保存。
标题带 `*` 表示仍有未保存内容。重要操作完成后，可在右上角菜单点击“保存”。

出现保存错误时，不要把关闭错误提示当作保存成功，也不要立即卸载或清除数据。
先保留当前编辑，记录提示并处理空间或文件问题后重试。
强制停止、系统杀进程或掉电可能丢失最后尚未保存的输入；当前没有持久编辑草稿恢复界面。
自动保存也不等于外部备份，建议定期导出 ZIP。

保存不会清空当前撤销历史，但切换/重新打开工程后不再保留之前的撤销记录。
删除整个本地工程不能通过标签编辑的撤销按钮恢复。

## 校对与批注

1. 在“校对”页点击“开始校对”，记录修改前的译稿。
2. 回到图像或标签视图，正常修改文字、分组和标记位置。
3. 在“校对”页点击“变更”，查看相对原译稿的差异；后续继续修改后可再次计算。
4. 需要说明原因时点击“批注”。已选中标签时批注属于该标签；未选中标签时属于当前页。
5. 用批注旁的复选框标记是否已解决，完成后点击“结束校对”。

结束校对会固定本轮完成稿，之后再编辑正文不会改写这份完成稿。
再次开始新轮次会询问是否替换旧轮次。分享 ZIP 不保留校对记录，不能用它归档旧轮次；
需要保留时不要替换。当前不提供多轮历史归档列表或校对记录导出入口。

校对信息和批注随本地工程的 LabelQt 元数据保存，但不进入安卓导出的 ZIP。
导入带校对信息的工程仍可在本地查看和编辑这些信息。
手机当前不提供桌面版的外部工程比较、人工配对和 HTML 报告导出入口。

## 分享给 QQ 或桌面用户

1. 打开右上角菜单，点击“分享 ZIP”。
2. 确认或修改 ZIP 文件名，未写 `.zip` 时会自动补齐。
3. 确认后等待保存和打包，随后在系统分享面板中选择 QQ 或其他应用。
4. 在接收应用完成发送，确认对方收到并能打开文件。

默认文件名来自原导入包名，输出统一使用 `.zip`，例如 `作品.7z` 分享为 `作品.zip`；
旧工程没有这项记录时，使用工程显示名。
同名分享不会覆盖之前的包。分享面板出现或关闭，都不表示对方已收到。
每次分享包含导出开始时的快照，不自动跟随后续修改。

接收方使用 Android 版可重新导入 ZIP；桌面用户解压后打开其中的 `project/project.txt`。
包中只包含当前正文 TXT 及当前页面图片。TXT 注释区统一留空，包括关联文件说明、普通注释、
校对记录、批注和稳定 ID；本地工程不会因此被清空。再次导入会生成新身份。
正文按经典 TXT 规则写出，依赖扩展元数据才能精确保留的额外空行等格式不随包保留。
ZIP 是正文交付包，不是校对信息的完整备份，也不包含仅供历史校对使用的图片。
正文和图像不会自动脱敏，发送前请检查内容。
若当前页面图片缺失，导出会报错；仅历史校对图源缺失不阻止正文导出。

## 存储与常见问题

首页或工程内右上角菜单的“关于”可查看软件版本、作者 Shitful，并打开 GitHub 仓库。
分享、重命名和批注等弹窗在可用高度较小时可滚动内容，底部操作按钮保持可见。

- **重复工程：**每次导入都是独立副本，从工程条目菜单删除不需要的副本。
- **分享缓存：**生成的分享包超过七天后可自动清理；新包会使缓存超过 2 GiB 时会被拒绝。
  它不是长期备份库。重新发送很久以前的内容时应重新导出，不要通过清除应用数据来释放这部分空间。
- **导入失败：**检查是否有多个 TXT、受限 ZIP 格式、不合法路径或超大内容；保留完整错误信息。
  具体资源上限及清理规则见 [构建与限制](android-build.md)。
- **只有图片却报 TXT 格式错误：**包内可能还有说明用的 `README.txt`，请移出后重试；不会自动忽略不合法 TXT。
- **文件名是 ZIP，实际不是 ZIP：**当前版本按内容识别，普通 RAR/7z 误写为 `.zip` 也能导入；
  改扩展名本身不会转换压缩格式，也不能解除加密或分卷限制。
- **没有图片：**检查是否只导入了 TXT，以及 ZIP 内路径是否与 TXT 引用一致。
- **工程显示名异常：**可从条目菜单重命名；反馈时提供原始 ZIP 完整文件名和导入方式，勿仅提供列表截图。

当前尚未提供：直接选择图片目录新建、页面管理/图片改名/补图、工程合并、全文替换、标签多选排序、
选区截图、独立 TXT/HTML 导出、完整偏好与草稿恢复界面。Python 自动化不在 Android 移植范围内。

真机试用已有 vivo/iQOO 反馈，但不同 ROM、QQ 版本、输入法和后台回收行为仍需验证。
反馈请附 APK 版本、手机/系统/输入法版本、操作步骤、完整错误提示；必要时提供去除隐私的最小测试包。
