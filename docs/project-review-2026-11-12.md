# 全项目安全与结构审查（2026-11-12）

## 范围与方法

覆盖共享解析/保存/恢复/图片事务、自动化任务、校对报告、桌面选择与编辑、移动工作区/传输/
搜索/画布，以及这些模块之间的调用链。结合静态阅读、可复现回归、Qt 模型/界面测试和动态检查。
检查对象包含当前工作树已有的 PDF、批注与移动交互改动，不等于只审查最近一次提交。
这不是所有平台、设备和恶意输入均无缺陷的保证。

## 风险与整改

| 优先级 | 问题 | 整改方向 |
| --- | --- | --- |
| P1 | 表格编辑排队后使用新的当前页，切页可能错写标签，立即保存可能遗漏输入 | 文本变更同步经过编辑服务，展示刷新单独延迟；测试编辑后立即切页/保存 |
| P1 | 最近工程菜单触发保存/另存时重建菜单，继续访问已销毁 action | 捕获路径值，整个交互流程延后到触发栈退出 |
| P1 | 不同 TXT 共用图片，图片重命名事务可能交错 | 资源目录级锁覆盖检查、移动、提交、回滚与恢复；保留 TXT 写锁 |
| P1 | 损坏的恢复副本可通过解析，却在提示准备时抛异常 | 分组格式在读取时验证，恢复候选逐项隔离错误，保留异常材料 |
| P1 | 本地编辑超过导入标签预算后，工作区列表跳过该工程 | 分离外部传输预算与本地列举，不能靠禁用合法编辑掩盖问题 |
| P1 | 图片完成通知中的首个接收方销毁缓存，后续通知继续访问旧对象 | `QPointer` 与代数校验中止通知，覆盖销毁与切工程清空两种回调重入 |
| P2 | 合并覆盖有未完成改名记录的 TXT，破坏自动恢复条件 | 写锁范围内复用恢复门禁 |
| P2 | 非法文本编码被静默替换，保存会固化损坏 | 共享严格解码，保留 BOM 识别；读取失败不推进基线 |
| P2 | 自动化安装依赖后解释器启动失败，任务无法结束 | `FailedToStart` 显式完成/重试，启动也纳入异步超时 |
| P2 | 隐藏标签仍留在详情/画布选择中，旧视口恢复跨工程应用 | 统一可见选择判断，图片切换清除旧恢复请求 |
| P2 | 移动搜索范围显示与实际查询在切工程后不一致 | 同步规范化后的页范围，等价查询不重复失效 |
| P2 | 跨页定位早于图片加载，定位请求被丢弃 | 画布持有绑定页面/标签身份的待定位请求，加载完成后消费 |
| P2 | 后台导出完成但分享面板未打开时无法重发 | 复核已发布文件后显式重新分享，不隐式重新保存或导出 |
| P2 | 分享缓存满时仍先生成文件，放大磁盘耗尽风险 | 写入前拒绝满缓存，导出预估与可用空间保护，保留最终配额验证 |
| P2 | 报告只限制图片宽度，长条图占用过多内存，旋转图比例错误 | 复用受限图片解码，双轴缩放、实际解码比例，HTML/PDF 共用 |

以上整改已实施并补充回归；不要将本表当作已通过的真机/跨平台验收清单。
同步校验写出端 Unicode，拒绝孤立代理项，避免内存字符串保存为替换字符。
表格提交后的刷新不再重选标签，并保护新打开编辑器的草稿；编辑器存在性统一由 `EditorStateController` 判断。

## 结构原则

- 不为审查而大规模改目录或增加全局管理器。持久化保护属于共享服务，前端只编排确认与呈现。
- 读取合法性只有一套规则；恢复预览、外部修改检测、正常打开不得各自用宽松解码器。
- 原子替换 TXT、协调图片事务、校验外部变化是不同职责，不用一个布尔“忙”状态替代锁协议。
- 外部输入预算、本地合法工程、输出缓存配额分别建模，不能互相借用后导致工程无故消失。
- 显示行号不是编辑身份；同步业务提交与异步视图刷新分开，不能用 `processEvents()` 掩盖时序问题。
- 画布负责图片加载与视觉定位，QML 页面编排不猜测一帧之后图片是否加载完成。
- 报告共用内容与图片解码；HTML 和 PDF 仅保留各自的排版实现，不复制业务匹配规则。

## 未消除的边界

1. **第三方 diff 内存风险。** `diff-match-patch` 的 Qt 6 容器失效问题仍依赖 CJK 策略门控。
   阈值不能证明混合文本安全。需要独立、可审查的算法修复与上游/模糊测试，见 TODO。
2. **归档解码资源耗尽。** 展开大小上限不限制 7z/RAR 解码器的内部字典分配和全部 CPU 开销。
   尚无可强制终止的隔离进程或硬内存配额；本轮不以“文件预算已有”宣称消除此风险。
3. **Android provider 阻塞。** 提供器的 query/open/read 可长期阻塞当前接收线程，后续导入受影响。
   `Thread.interrupt()`/Future 超时不能保证终止底层读取；需要可终止 I/O 或独立进程边界。
4. **协作式文件锁。** 不遵守锁协议的外部编辑器/图片工具仍可在最后校验与系统调用之间修改文件。
   本轮不能提供跨任意工具的原子 compare-and-swap 或文件系统断电保证。
5. **平台验证。** Linux 主机测试不能替代 Windows 原生行为、Android IME/旋转/低内存/强杀、QQ 提供器
   与接收端验收。内存检查也仅覆盖执行到的路径，并不证明整个程序无内存错误。
6. **主机 Qt Quick 警告。** Qt 6.11.2 的 OpenGL 线程化渲染在首次显示内嵌 PNG 富文本时出现
   `QObject: Cannot create children for a parent that is in a different thread`。
   GDB 将其定位到渲染线程内 `QQuickPixmap::load` → `QQuickPixmapReader` 以 GUI 线程的 QQmlEngine
   为父对象创建 QThread。普通运行像素断言通过；`QT_FATAL_WARNINGS=1` 会因此主动中止。
   这不是已证实的 Android 6.10.2 崩溃，也不能因此忽略线程警告。未屏蔽日志或添加隐藏控件预热，
   需独立验证 Qt 版本差异与公开渲染接口的规避方式。
