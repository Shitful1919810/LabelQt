# LabelQt 产品改进提案

状态：待审阅，本文的四项产品功能尚未实现。本文区分当前已有的安全修复与后续产品设计，不作为现有功能说明。

## 设计前提

使用者通常一边查看漫画大图，一边反复编辑短文本，随后与另一份稿件进行校对。软件首先需要保护稿件、保持图文对应、减少视线和操作切换，再考虑扩展协作能力。

继续使用 Qt Widgets 和现有主界面，不增加首页，不更换 UI 框架。常用编辑保持轻量；低频批量操作集中在专门窗口，危险操作展示准确的最终影响。不把业务状态、文件操作和撤销逻辑塞进窗口类。

本轮已补充原子写入、重命名失败回滚、保存提交与撤销清理的协调、文本保真及日志窗口生命周期保护。它们是下述功能的基础，不等于恢复中心、页面管理新布局、全文替换和审阅进度已经开发完成。

## 一、工程恢复中心

### 推荐表现

入口放在“文件 → 备份与恢复…”。正常启动不弹窗；只有检测到未完成文件事务，或确有比正式稿更新的可恢复编辑时，显示一条非模态提醒。未解决的文件事务先阻止该工程继续写入，允许只读检查和另存恢复副本。

恢复窗口采用左侧记录列表、右侧详情，不做多层卡片。列表显示时间、记录类型、涉及页数和状态；详情显示原工程、图片目录、文本变化摘要和缺失图片数量。

主要动作：

- “预览”：只读查看候选稿，不切换或覆盖当前工程。
- “恢复为副本…”：默认动作。将候选稿恢复到能正确解析图片引用的位置，并为当前原稿保留备份。
- “替换当前稿…”：次要动作。先提交当前编辑、解决外部修改冲突，再明确确认。
- “打开所在文件夹”：供用户核对原文件和恢复记录。

未完成重命名事务单独显示“恢复原文件名”与“完成此次操作”。只有核实所有涉及文件的身份和内容后才允许执行；无法证明文件对应关系时只提供诊断清单，不自动猜测。

### 保存冲突

检测到工程被其他程序修改时，弹窗展示磁盘版本与当前编辑版本的修改时间，提供“比较”“另存当前编辑”“重新载入”。覆盖操作必须明确确认，不能用一个默认选中的“是”替代冲突处理。

“重新载入”同样先处理未保存编辑。对比复用当前工程对比能力，不另做文本差异引擎。非协作程序仍可能在检测后再次写入，文案不承诺对任意外部程序提供完全排他的保存。

### 实现方式

- 新增小型恢复记录服务管理备份索引、工程身份、文本摘要和恢复状态；`ProjectController` 继续拥有工程打开和保存语义。
- `SessionStateStore` 只记录本机入口和窗口状态；业务快照、文件映射不塞进 QSettings。
- 事务记录应版本化，包含原/目标工程内容摘要、每个文件的身份验证信息和可恢复阶段。当前 `.labelqt-rename-*.json` 只提供路径映射，不能直接据此实现可靠自动回放。
- 保存使用成功加载/保存时的磁盘版本作为比较基准，修改时间和大小用于快速筛选，内容摘要用于确认。
- 自动备份不被直接等同于可在任意目录打开的工程；恢复时必须重新处理图片相对路径和来源元数据。
- 首版不自动删除用户手工备份。自动记录清理策略通过 AppPreferences 提供，未解决事务的材料不能被清理。

### 验收重点

保存失败不提示成功；中途退出后能识别待恢复事务；恢复失败不覆盖原稿；同名图片交换不能猜错；恢复副本重新打开后图片和稿件一致；不存在恢复候选时不打扰用户。

## 二、页面管理整理

### 推荐布局

保留左侧较小预览、右侧单表格、底部格式输入，避免重新出现两张表。

| 表格列 | 含义 |
| --- | --- |
| 当前图片 | 本次打开窗口时的图片引用，重排不改变它的身份 |
| 待应用目标 | 已加入草稿、点击确定后才生效的目标；没有改动显示短横线 |
| 输入预览 | 当前格式串若应用于选中范围，将产生的结果或错误 |
| 原页序 | 排序参考，可收窄，不能充当页面身份 |

表格顶部保留移动和移除按钮，增加“全部 / 待处理 / 有问题”视图筛选和“待处理 N 页”的计数。筛选只影响展示，不删除草稿内容；最终确认始终覆盖完整草稿。

格式区明确显示作用范围：“已选 N 页”或用户显式选择的“全部页面”。没有选择时禁用“加入待处理”，不隐式把零选中解释为处理全部。按钮改叫“加入待处理”，因为缺失图片的操作不是文件重命名。

右键菜单提供“清除此页待处理操作”，顶部提供“清空待处理”。删除页面时默认同时移除该页的待处理文件操作，不能留下一条不可见的磁盘改名指令。

### 缺失图片修复

保留现有格式串批量匹配，额外提供两种直接入口：

- 单页：“指定图片…”打开文件选择器，选择后立即刷新左侧预览和待应用目标。
- 多页：“在文件夹中匹配…”选择目录，优先精确名称，再尝试同名主体与可读图片扩展名；多候选留给用户选择，不直接采用第一项。

现有图片改名不改变扩展名。缺失图片修复允许不同扩展名，但只更新工程引用，不修改被指定图片的内容。跨目录来源必须明确保存为相对引用还是受控复制，首版推荐相对引用，并在另存、备份恢复和合并中复用同一策略。

### 最终确认

点击“确定”时，展示完整影响清单：重排 N 页、移除 M 页、改名 K 个文件、修复 L 个引用。文件改名与仅修改引用分组显示；明确是否自动保存、是否清空普通撤销历史。没有真实文件操作时不使用危险操作警告。

确认失败留在窗口，草稿不丢失；成功后才关闭。不可恢复的文件错误转入恢复状态，不允许按旧草稿直接重试。

### 实现方式

- 引入 `PageManagementDraft`，集中持有原始快照、保留页面、显示顺序、按稳定页面身份关联的 pending 目标。
- 当前输入只产生候选计划，不写入 pending。表格 model 从草稿和候选计划读取数据，不各自复制业务映射。
- 原有 `ProjectImageRenameService` 负责格式串和引用规划，`FileRenameTransaction` 负责文件移动，`ProjectController` 负责工程提交。
- 窗口内可对草稿操作做局部撤销；它与主界面工程撤销栈分开。确认之前不能修改真实工程或图片。
- 提交时按完整最终状态校验冲突。交换文件名必须允许；与未参与操作或外部图片冲突必须阻止。

### 验收重点

单选改封面只影响一页；分两次排队不会覆盖第一批；移动顺序不清空 pending；移除页面不遗留隐藏操作；筛选不会改变提交范围；预览与实际执行结果一致。

## 三、工程全文查找与替换

### 推荐表现

使用可收起的查找面板，默认停靠在右侧标签列表下方，打开时不覆盖左侧大图。普通查找只显示输入框、上一项/下一项、命中计数；展开“替换”后才增加替换文本与作用范围。

默认查找全工程，结果按工程页序和标签顺序排列。可切换当前页、指定页码范围，并选择分组。当前筛选条件必须在面板内明确显示，避免“搜不到”实际上是被分组过滤了。

点击结果只定位到对应页和 label；输入查询时不自动切换主界面页码。匹配词高亮不进入标签正文，也不改变正常选择同步的来源语义。

### 批量替换

“替换当前项”直接进入普通撤销；“预览全部替换…”打开轻量清单，显示页面、标签、原文和替换后文本，用户可以排除个别命中。确认显示实际影响的标签数与匹配数，整批一次撤销。

查询或替换内容支持真实换行，必须区分文本中的换行和输入的两个字符 `\n`。首版只提供普通文本和大小写开关；正则后续再增加，不默认把用户输入解释成表达式。

### 实现方式

- 独立 `ProjectTextSearchService` 返回结构化命中及原文区间，不读取或修改控件。
- 搜索范围和分组过滤复用核心语义，不把当前 UI 行号直接存成 label 身份。
- 替换通过 `LabelEditController` 的批量编辑入口提交，复用现有单标签修改辅助逻辑并生成一个撤销命令。
- 预览关联工程版本和原文；预览后若文本、顺序或工程发生变化，确认前重新验证，不能把旧区间应用到新文本。
- 长工程可后台搜索，但结果只能绑定启动时的工程快照；用户更改查询时过期结果自动丢弃。
- 查找、下一项、上一项快捷键通过 AppPreferences 配置。具体键位在现有快捷键冲突检查通过后确定，不强占已有绑定。

### 验收重点

中文、日文、emoji 和换行定位正确；重复命中无偏移错误；批量替换支持完整撤销/重做；外部修改或切换工程后不能应用旧预览；过滤条件与统计一致。

## 四、审阅进度与人工匹配

### 推荐表现

在现有校对表格增加一个紧凑的审阅状态列，使用图标和 tooltip，不靠颜色单独表达。首版三个状态：“未查看”“已查看”“待确认”。新增状态筛选和“下一条未查看”动作，保留现有页面、变更、摘要筛选的交集语义。

选中、悬停或滚动经过一行都不自动标记已查看。只有用户执行确认动作才改变状态，避免浏览动作误报进度。支持对选中的多项批量标记。

窗口底部提供简短批注区域，默认收起；批注属于审阅记录，不插入漫画译文。HTML 报告可包含状态和批注，导出前明确范围，例如“当前筛选 18 项，其中待确认 4 项”。

### 人工纠正匹配

对误判为新增/删除的条目，在上下文菜单提供“与另一侧标签配对…”。使用现有两侧图片预览和候选文本列表，展示坐标、原文、目标文本；用户确认一对一对应关系后重新计算差异。

已配对条目可“取消人工配对”，恢复自动匹配。跨页配对先由页面配对关系决定，不能随意把不相关页面上的标签拼成一项。人工配对必须显式展示，不能伪装成自动匹配结果。

### 实现方式

- 审阅记录与 diff 结果分开存储；`ProjectComparisonService` 仍输出差异，UI model 组合审阅状态后呈现，不在 renderer 中写业务状态。
- 记录绑定比较上下文和变更指纹，不绑定瞬时表格行号。上下文至少包含当前工程/目标稿身份与基线摘要；变更指纹包含双方页面身份、文本和相关属性。
- 文本或标记变化导致指纹变化时，旧“已查看”不能自动转移；退回未查看并保留旧批注为历史线索。重复文本、相同坐标等存在歧义时，宁可要求重确认，不猜测归属。
- 工程内基线的共享审阅记录可放入统一 `LabelQtMetadata` 的版本化 section；外部工程比较默认只存本机会话记录，避免未经同意把对方稿件信息写入当前工程。
- 人工配对由独立匹配约束结构进入比较服务。遇到删除、重排或目标稿更换，验证约束后再使用，不用 UI 特判强行拼接两行。
- 状态和批注编辑支持撤销；外部比较窗口使用局部审阅撤销，避免污染主工程的文本编辑历史。持久化范围需在对应入口明确。

### 验收重点

重新打开同一比较可以恢复进度；稿件有变化不会误继承“已查看”；筛选不丢记录；人工匹配可撤回且满足一对一约束；报告与窗口状态一致；不要求实现 Word 式接受/拒绝修订。

## 建议推进顺序

| 阶段 | 交付范围 | 原因 |
| --- | --- | --- |
| A | 恢复协议、外部修改检测、最小恢复入口 | 先保障可恢复性，避免功能增多后放大文件风险 |
| B | 页面管理统一草稿、明确范围、待处理操作与直接指定图片 | 现有工作流使用频繁，收益明确，且依赖 A 的提交与恢复语义 |
| C | 普通全文查找、替换预览与批量撤销 | 对翻译统一术语和校对修订有直接价值 |
| D | 审阅状态、批注，再加入人工配对 | 先建立可信的记录身份，再扩展复杂匹配能力 |

每阶段独立验收，不把四项合成一次大改。优先确认本提案中的恢复默认方式、页面作用范围和审阅记录存放位置，再细化具体界面。
