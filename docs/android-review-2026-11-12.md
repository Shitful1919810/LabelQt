# Android 交付前检查（2026-11-12）

> 后续需求已将安卓分享改为保留 TXT 注释区及 PC 兼容的校对/批注记录。
> 下述“无注释分享”仅是当时的审查记录，现行行为见 android-user-guide.md 与 android-development.md。

## 范围与整改

本次重点复核移动文档/撤销、模型与手势生命周期、工作区异步传输、导出副本隔离、
归档路径和预算校验，以及它们依赖的共享编辑与序列化代码。不是对所有平台无缺陷的保证。

| 问题 | 处理 |
| --- | --- |
| 删除后显示编号仍使用存储索引，与桌面筛选编号不一致 | 两端共用 `LabelVisibility`；显示编号、存储索引、UUID 分离；覆盖删除/筛选/撤销/保存再导入 |
| 新分组允许 `-`、换行等不可序列化内容，随后保存失败 | 格式验证由序列化层公开，编辑入口拒绝无效修改，移动界面保留错误输入 |
| 批量移动重复目标时，撤销可能恢复到中间位置 | 修改前拒绝重复目标，不生成部分命令或撤销历史 |
| 打开工作区借用模型字符串跨越保存信号 | 打开入口持有参数副本；测试保存回调改变调用方字符串后仍打开原目标 |
| 长提示/输入在小屏横屏下挤出弹窗操作区 | 共用限高可滚动弹窗，提交成功才关闭；关于页复用同一布局 |
| 提交弹窗的取消按钮配置被父 Dialog 的默认值覆盖 | 标准按钮改由 Dialog 统一管理，并断言确认/取消两个按钮都存在 |

性能调整限定在明确的重复工作：移动标签刷新预建完整分组索引，避免每条标签线性查找分组；
样式读取不复制完整样式；画布查询编号不再构造整页临时索引数组。没有增加跨工程缓存或第二套身份状态。

安卓分享显式使用无注释序列化策略，只复制当前正文和当前图源；本地保存、导入和通用传输默认策略不变。
不通过删字符串拼出“干净 TXT”，不会清空活动工程校对信息。分享不是校对记录备份。

## 回归与剩余边界

本轮验证结果：移动主机 5/5、桌面 13/13 测试组通过；快速检查和四语言检查通过
（673 条 source、719 组 context/source）。关于页及分享弹窗完成离屏 OpenGL 截图检查；
APK 构建成功，版本 `0.1.0-android-preview.1`，v2 调试签名、ZIP 与 86 个原生库的 16 KiB 对齐通过。
没有进行 Android 真机测试。Qt 软件渲染测试中的 Material 阴影层不能代表实际 OpenGL 外观。

- 回归入口：`ctest --preset mobile-host-debug` 和 `python scripts/devtool.py check --mode all --preset linux-debug`。
- 重点测试：无效分组不改变工程、重复移动不改变撤销栈、保存回调中的参数寿命、双端编号一致、
  无注释导出不修改原工程、导出时继续编辑、工作区删除、迟到 diff、窄屏/横屏弹窗布局。
- 新关于页不引入依赖；四语言词条、实际 APK 版本、签名与 16 KiB 对齐单独验证。
- 主机 Qt Quick 测试不覆盖 Android 输入法、厂商键盘遮挡、QQ 文件提供器、系统强杀及低内存回收。
  这些仍需真机回归，不能承诺所有未保存输入在进程死亡后恢复。
- libarchive 解码器本身的内存/CPU 开销不等于展开文件预算；恶意大字典压缩包仍有资源耗尽风险。
  当前文件大小/条目/路径预算不是进程级隔离，后续应单独评估解码资源约束。
- diff-match-patch 的已知 cleanup 风险仍依赖现有 `TextDiffService` 策略门控，本次未修复第三方库。
