# Android 首页与分组样式审查

## 范围

本轮沿工程入口、活动文档、标签模型、画布手势、校对异步任务、归档传输、工作区生命周期进行人工检查，
同时抽查共用保存事务、外部文件监控、图片加载和桌面自动化进程边界，并运行桌面与移动端完整测试组。
这是风险导向审查，不表示每个文件逐行审计，也不能保证不存在未知问题。

## 已整改

| 问题 | 处理 |
| --- | --- |
| 首页只有两个入口，工程管理藏在抽屉中 | 首页直接展示工程列表；抽出 `WorkspaceBrowser`，与抽屉复用模型及管理请求 |
| marker 样式硬编码，无法区分分组 | 模型输出偏好设置中的颜色与形状，按完整分组序号定位；选中外圈独立于分组填色 |
| 选择、刷新及文本提交都重置标签模型 | 可见身份不变时只通知实际变化的 role，保留 marker 实例和进行中的非冲突交互 |
| 撤销新增分组后筛选残留失效名称 | 实际可见组从当前工程取交集，保留筛选意图用于重做，禁止向不存在的组新增标签 |
| 首次列出工程在界面线程解析全部工程 | 复用串行后台维护任务加载列表；不与导入、导出或删除并发访问工作区 |

## 保持的安全边界

- 普通编辑继续走 `LabelEditController` 与同一个撤销栈，没有新增 QML 正文写入路径。
- 后台传输、校对只持有值快照；校对结果验证文档会话及版本，不把旧结果提交到新工程。
- 删除当前工程先保存、移出目录，再关闭会话并停止定时器；清理不处理普通工程或未解决事务材料。
- 共用保存通过文件锁、内容版本校验、原子替换和单份上一版本备份保护存档；不是无限备份。
- 没有改动桌面的自动化、校对清理策略或 LabelPlus 文档格式，没有引入新的依赖或许可证义务。

## 验证与剩余边界

回归覆盖首页打开与空态、小屏/宽屏布局、分组样式及筛选、模型不重置、撤销分组后新增标签、
marker 颜色/形状更新和手势取消；原有导入攻击、保存冲突、删除/缓存、校对会话失效测试继续保留。

本轮桌面 13 组、移动 5 组测试及快速/翻译检查全部通过，主机 OpenGL 离屏首页截图检查通过。
Android ARM64 APK 已交叉编译打包；主机图形验证不代替手机操作验证。

仍需真机验证中文输入法预编辑、后台强杀和厂商 QQ 文件提供者。移动预览尚无持久编辑草稿恢复 UI，
成功保存前的输入仍可能因强杀丢失；大图仍是有界解码而非分块引擎。
后台工程扫描仍需解析工程，工程很多时可能耗时，但不再阻塞界面线程。
