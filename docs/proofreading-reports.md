# 校对报告：HTML 与 PDF

## 入口与内容

- 桌面比较窗口的“导出报告”菜单提供 HTML 和 PDF；两种格式均使用当前表格筛选后的变更，
  包含页面、类型、摘要、审阅状态筛选，空结果不能导出。
- Android 工程菜单提供“分享校对 PDF”。选择文件名和全部页面/当前页面后生成报告，再调用系统分享。
  需要已有校对轮次；进行中的轮次对比当前稿，已完成轮次使用冻结的完成稿。
  移动端不把搜索关键词或批注列表筛选隐式套用到报告，导出范围只由此弹窗确定。
- 两端使用同一个 PDF 渲染器：A4 纵向、双侧图片和 marker、差异表、批注、审阅状态、页码。
  长文本可以跨页，续页重复表头，文字可选择和搜索。图片缺失时显示占位文字，仍保留差异。
- HTML 与 PDF 的内容语义相同，PDF 不是网页截图，也不承诺浏览器 CSS 的像素级复现。
  HTML 适合屏幕阅读，PDF 适合打印和直接转发。两者均不是可重新导入编辑的工程。
  要保留可继续校对的数据，桌面保存 TXT 和图源，Android 分享工程 ZIP。

## 模块边界

`ProofreadReportService` 接收值快照、结构化变更、文案及范围描述，不读取活动窗口或磁盘工程 TXT。
`ProofreadReportContent` 统一左右图配对、marker、摘要、diff、批注和审阅状态内容；
HTML 与 `ProofreadPdfReport.cpp` 共享这些规则，文本差异仍经过 `TextDiffService` 安全策略。
默认报告文案由同一工厂提供；前端只补充当前比较语境的左右标题。

PDF 使用现有 QtGui 的 `QPdfWriter`、`QTextDocument`，不引入 Qt PrintSupport、WebEngine、
GPL-only 模块或外部浏览器。每组图片独立排版，限制同时解码的预览图数量；最多接受 100,000 项变更，
超过时要求缩小范围。单页海量文本仍可能消耗较长的布局时间，取消为协作式而非强杀线程。

HTML/PDF 的图片预览统一复用 `ImagePageCache::previewLoader`，保留 EXIF 方向处理和读取前后
文件摘要校验。来源图最多 32 Mi 像素，预览长边最多 2048 像素；宽度和高度同时受限，
不再只缩小横图。HTML 按实际解码后的尺寸计算比例，避免旋转图片变形。
超限、缺失或无法可靠读取的图片显示不可用占位，不影响文字差异导出。

`ProofreadReportShareService` 负责移动校对快照到报告参数的适配。
`MobileWorkspaceController` 只编排保存、捕获快照、串行任务和通知。
ZIP/PDF 共用 `WorkspaceStorageService::createSharedFile` 的暂存、文件名校验、只读发布和缓存配额，
平台桥只接受 outgoing 内的 ZIP/PDF 文件并授予精确的临时读取权限，不接受 PDF 作为工程导入。

## 失败、取消与并发

- 输出通过 `QSaveFile` 提交，禁用非原子回退；PDF writer 析构、尾部写完后才提交。
  出错或中止不覆盖已有目标。桌面另保留既有暂存到目标的安全发布流程。
- Android 生成失败时不发布 outgoing 文件、不触发分享。文件发布完成后才收到取消时，
  抑制分享通知，已完整生成的文件按正常缓存保留期回收，不把半成品交给其他应用。
- 导出捕获不可变工程快照，期间文字编辑不影响这份报告。工作区导入、删除、清理和其他导出串行，
  不允许后台同时删除所用图片。未来加入移动图片改名或补图必须接入相同资源协调。
- PDF 与 ZIP 共用七天缓存保留及 2 GiB 总配额。交给 QQ 不代表对方已收到。

## 验证

`ProofreadPdfTests` 在桌面和移动主机目标中共用，覆盖中文长文本、多页、图像缺失、页面批注、
范围过滤及失败/取消不覆盖旧文件；安装 Poppler 时进一步提取 PDF 文字检查完整性。
`MobileWorkspaceTests` 覆盖异步快照、取消和传输互斥；`MobileShellTests` 覆盖分享弹窗和小屏布局。
真机仍需检查系统字体、中文 IME、后台切换、系统分享取消及 QQ 实际接收。
